## 群内使用

- `/漫画`：先发送简短介绍和用法，再单独发送游戏分享卡（`type: share`、`shareType: character`、`resourceId: "3799187"`），不把链接拼进介绍文本。
- 回复群内一张原图，发送 `/保存 姐妹日常 下午茶`：保存到指定分区并命名；图片名称可不填，可替换为其余四个分区（含 `私密相册`）。
- 群内保存和移动指令兼容「脑洞大开」写法，统一归入「大开脑洞」，不创建新分区或改动图片名称。
- `/移动图片 8 姐妹日常`：将编号 8 的图片移动到姐妹日常，游戏大图里也可选择目标图集并点击「移动图片」。保留编号、原图、名称和收藏；目标已有同图（含已删除记录）则拒绝移动并保留原图，不覆盖或合并。
- `/删除图片 8`：按图片编号删除（不限上传者，当前妹子群成员可管理）。大图与保存回复显示编号；页面大图中也可点击「删除图片」并确认。
- `/恢复图片 8`：恢复误删图片，保留原编号、原图、名称与收藏。采用软删除，删除期间不提供列表、原图和预览；重复删除或恢复不会反转状态。不支持按模糊名称批量删除。
- 无需额外 @ 机器人；沿用群的 `slash_cmds` 功能开关。
- 仅在指定妹子认证群收图，核验指令发送者的当前成员身份。回查原消息后下载原图，不信任引用中嵌入的地址。同一分区的同一图片重复保存不会新增副本。

游戏分享卡按《游戏卡入门指南》第八节封装，由现有账号 Socket.IO 连接发送并等待明确 ACK；官方 Bot 文本接口只承担介绍文字。分享卡独立记录到出站队列，保存 `content_type=share` 和平台消息编号；超时或不明确失败不改发文本、不自动重发。

## 共享服务

机器人与网页共用 `runtime/gallery.py` 的 SQLite 存储，原始图片字节和元信息在同一事务保存；不会依赖易失效的群图 URL。收藏按玩家隔离。默认数据文件 `data/gallery.db`，不在静态发布目录。

安装根目录 `requirements.txt` 后，配置环境变量：

| 变量 | 用途 |
| --- | --- |
| `DZMM_GALLERY_GAME_ID` | 此游戏玩家 JWT 的精确 audience，支持正整数 ID 或规范 UUID；通过平台联调确认，不能沿用工位游戏配置 |
| `DZMM_GALLERY_DB` | 机器人与 API 必须指向同一个持久文件；默认项目下 `data/gallery.db` |
| `DZMM_GALLERY_ORIGINS` | 允许的网页来源，逗号分隔；不使用通配符。平台沙箱若发送 `Origin: null`，须明确配置 `null` |
| `DZMM_GALLERY_PORT` | 本机监听端口，默认 8775 |
| `DZMM_TOKEN_FILE` | 现有机器人账号会话文件的位置，用于读取当前群成员；不得放入网页包或提交仓库 |

```powershell
$env:DZMM_GALLERY_GAME_ID='<此游戏 JWT 的 audience>'
$env:DZMM_GALLERY_ORIGINS='<已确认的平台来源>'
python -m runtime.gallery_api
```

服务只监听 `127.0.0.1`。上线须由 HTTPS 反向代理提供访问，并将 `publish/config.js` 的 `GALLERY_API_BASE` 设置为实际 HTTPS 服务地址（含 `/api/gallery`）。服务自身托管页面时动态 `/config.js` 使用同源接口。

公开接口：`GET /api/gallery/items`、`GET /api/gallery/images/{id}`，不要求玩家 JWT，不返回上传者昵称、ID、来源消息和个人收藏状态。

私人接口 `GET /api/gallery/me`、收藏接口 `PUT /api/gallery/images/{id}/favorite` 验证 Gamefy RS256 JWT（官方 JWKS、issuer、有效期、精确游戏 audience）。`POST /api/gallery/upload` 和 `PUT /api/gallery/images/{id}/title`、`PUT /api/gallery/images/{id}/category` 另外核验当前妹子群成员，不能使用历史名单放行。令牌只放 Authorization 请求头；公开原图响应带名称对应的 Content-Disposition。

图片限 JPG、PNG、WebP；每张 10 MB、4000 万像素；网页每次最多 30 张/总共 100 MB。保存前实际解码检查。群原图下载目前仅支持已观察到的 `https://rls.cheggpt.com`，不跟随跳转。原消息无法找到、来源变化、名单不完整或平台不可用时拒绝保存并反馈；实时引用缺失时，只回查同一条保存指令并核对发送者、群和指令文本，再查对应原图；归档仅提供时间索引，绝不以归档或引用内的 URL 作为原图依据。已知时间时按时间定位，无时间索引时最多查最近 500 条。
