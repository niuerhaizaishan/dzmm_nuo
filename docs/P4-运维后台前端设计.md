## 2. 设计决策

### 2.1 信息架构（IA）

左侧固定侧边栏，按"使用频率 × 风险"分三组：

```
监控
  ├ 📊 总览            ← 默认页：状态卡 + 快捷操作 + 启动自证 + 群状态
  └ 💓 健康与日志
运行时配置
  ├ 🎚️ 功能与参数      ← 合并后的简化版（见 §3）
  ├ 🎭 人设文本
  └ 📝 提示词
危险区
  └ ↩️ 回滚与重置      ← 单独分组、置底，防误触
```

- 侧边栏带**计数徽章**（功能 68、提示词 41…）与**运行状态点**（badge--pulse）。
- 统一 header：面包屑 + 主题切换（暗色默认，跟随系统，localStorage 记忆——app.js 已实现）。
- 移动端：侧边栏抽屉化（base.css 已带 ≤768px 断点）。

### 2.2 总览页信息层级（preview.html 主体）

1. **告警条**（仅异常时出现：巡检失败 / token 过期 / restarts>0）
2. **状态卡格**（4 张 stat-card）：容器 / 登录态 / 群与 Bot / 出站队列
3. **快捷操作 + 启动自证**（双列）：
   - 快捷操作：热加载配置、立即巡检、重登账号、拉取日志
   - 启动自证：把 P5/P7/P8/P11/P12 启动日志**页面化**（配置来源=file、prompt 41/41、功能 68/68…），一眼回答"到底生效没有"
4. **群状态表**：4 群 ×（人设 / Bot 通道 / 功能摘要 / 最近活动）——**以群为主视图**
5. footer：版本与构建信息

### 2.3 主题与视觉

- 暗色默认（运维场景长时使用），亮色可切；色板 GitHub 风格（bg-0~3 层级、accent 蓝、ok/warn/bad 语义色），base.css 已定。
- 密度：紧凑（fs-base 13px、sp-4 16px 主体间距）——运维后台重信息密度，轻装饰。
- 组件零装饰原则：层级靠卡片边框与底色差，不靠阴影堆叠；动效只用于状态反馈（fadeIn/pulse），尊重 prefers-reduced-motion。

## 3. 功能配置页简化设计（本轮核心调整）

**问题**：现 features 页把 68 个功能开关逐键铺开、tuning 67 个参数逐项配置——
粒度是"给开发者看"的，不是"给屋主用"的。屋主的高频问题只有三个：
「这个群现在开着什么」「我想关掉/打开某个能力」「我改过哪些参数」。

### 3.1 简化原则

1. **以群为主视图，不以开关为主视图**：默认看到 4 张群卡，每张列出该群**启用中的能力摘要**（badge 流式排列），点「调整」才进入该群的能力清单。
2. **高频白名单前置**：真正会动的键（约 10 个：at_only、slash_cmds、quote_reply、devil_roast、devil_cold、trend、recap、fortune、profile_scan、memory_report）做成卡片上的**直接开关**（toggle，改了即进 dirty 计数、统一保存）。
3. **长尾折叠 + 搜索**：其余 50+ 键收进「高级」折叠区，默认收起，提供搜索框（app.js 的表格搜索已具备）。
4. **参数页只显示"已覆盖"**：tuning 的原则是"没覆盖 = 今天的行为"，所以默认**只列已覆盖的参数**（当前 15 个），其余不展示；「+ 新增覆盖」入口按需加。
5. **合并功能与参数为一页**：「功能与参数」双 tab（tabs 组件现成），减少一次页面跳转；两页本来就是"这个群的行为"一件事。

### 3.2 简化后的页面结构

```
功能与参数页
├─ 群选择器（4 个 tab：认证群 / 玫瑰房 / 上班群 / 茶水间）
├─ 该群能力摘要卡
│   ├ 高频开关区（10 个 toggle，直接改）
│   └ [高级 ▸] 折叠区（其余键 + 搜索框）
├─ 已覆盖参数表（默认 15 行：参数名 / 值 / 生效群 / 恢复默认按钮）
└─ 保存条（dirty 计数 + 保存 / 放弃 —— app.js 已有 dirty 机制）
```

### 3.3 不变的部分

- 人设文本、提示词页：内容编辑性质，粒度合理，仅做组件化对齐（card/tabs/btn/toast）。
- CSRF / 双确认 / 回滚机制：后端逻辑一律不动，纯前端重组。
