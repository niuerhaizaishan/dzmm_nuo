# P12-BA：运势的称呼**按性别**（不能逮谁叫谁姐姐）

> 屋主 2026-09-30："**还有，运势你也不能逮谁叫谁姐姐呀，要看性别的呀**"

## 1. 现象

茶水间（792 人，男女都有）的运势卡最后那句点评，**见谁都叫"姐姐"**：

```
🤖 🔮 苏白 今日运势 …        ← 苏白是男生
墨莲姐姐今天本命土受生、名格火比和…
```

认证群那边看不出来（那是妹子认证群，几乎都是女生），所以一直没暴露。

## 2. 根因：**提示词里有规则，输入里没数据**

`FORTUNE_PROMPT` 其实早就写了"女生叫 X 姐姐、男生叫 X 哥哥"，但两件事把它废掉了：

1. **`fortune()` 拼给模型的输入里从来没有性别**：
   ```
   用户主名：苏白
   命盘：… / 四维：… / 最近发言：…
   ```
   模型手里只有一个人名和一堆命盘数字 —— 规则要它"看性别"，可它**没得看**；
2. 提示词第一句是"给**姐姐**的今日运势"，**示例只有女生那一条** ⇒ 语气 + 示例
   把模型训成了一律叫姐姐。

这跟 P12-AL 那个"基础提示词 13 处姐姐、4 个示例全是姐姐"是**同一类毛病**
（见 `tests/test_gender_and_at_only.py` 开头）：**改一句规则说明没用，要补示例**。

## 3. 修法

| # | 改动 | 说明 |
|---|---|---|
| 1 | `runtime/fortune.py::_gender_label_of(uid, cid)` | 档案优先（`profiles`），档案没写就**实时查一次平台**（`runtime.members._gender_of`），都拿不到 = "未知"；失败**留痕不炸**（`_warn_once`，不吃掉异常） |
| 2 | `fortune()` 把 `性别：X` 作为**输入字段**交给模型 | 规则要能用，先得有数据 |
| 3 | `prompts/FORTUNE_PROMPT.md` + `brains.FORTUNE_PROMPT`（逐字节一致） | 第一句改成"给**群友**的今日运势"；规则改成"**先看输入里的「性别」再决定怎么叫**"，并写死"**绝不许把女生以外的人叫姐姐**"；**补男生 + 未知两条示例** |
| 4 | `runtime/trend.py` + `TREND_PROMPT` | 同一个毛病在「过去 7 天运势趋势」也有（提示词写死"叫对方姐姐"）⇒ `week_trend` 把性别传给 `generate_trend` |

称呼口径（三档，和 P12-AL 的对话口径一致）：

| 性别 | 叫法 | 语气 |
|---|---|---|
| 女生 | 「主名」+姐姐 | 可以更软更黏 |

| 未知 | **只叫「主名」** | 不许自己补"姐姐/哥哥" |

## 6. 复盘

- **"提示词里写了规则"不等于"规则能用"**：模型只能看输入。这次是规则、语气、示例
  三处都在往"姐姐"上推，而**输入里连性别这个字段都没有** —— 先问"它凭什么知道"。
- **示例比规则更有说服力**（P12-AL 就吃过一次）：只加一句"按性别叫"没用，
  必须补一条男生的问答当锚点。这次三条示例（女/男/未知）配齐。
- **同一个 bug 会在同族功能里再长一次**：改运势卡时顺手查了「运势趋势」，
  果然也写死了"叫对方姐姐"。
