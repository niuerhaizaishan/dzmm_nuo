# P12-AR：续期循环停摆没人知道（心跳只写在一条路径上）

> 屋主 2026-09-29：**"token续期的那事儿怎么样了？"**
> 这一轮不是修"续期失败"，是修**"续期挂了没人知道"**。
> 上一轮 P12-AJ 修的是"401 误判导致自杀重启"；这一轮顺着体检发现两个新窟窿。

## 1. 先量现状（13:22 实测，P12-AJ 之后）

| 项 | 值 |
|---|---|
| 业务探针 | `ok`（0.2s）——会话真的活着 |
| 循环心跳 | `session_state.json` 1 分钟前写过 |
| token | 还剩 25 分钟（一小时一续） |
| 失败连击 | `{"streak": 0}` |
| `token.emergency` / `bot.paused` | 都不存在 |
| 今天自杀重启 | 3 次（06:22 / 07:22 / **09:37**），**全在 P12-AJ 之前**；之后 0 次 |

**P12-AJ 的 401 分支至今没被真实触发**（`NOTE=0`、`SESSION_DEAD=0`）。也就是说
"401 不再自杀"这条只在单测里验过。作为替代，当场验了它的**判别器**：
`renew_token._api_probe()` 返回 `ok` → 真出现 401 时会走 `NOTE:`、不重登 ✅。

顺带排除一个怀疑：cookie 里 `refresh_token` 只有 12 字符（`access_token` 744），
看着像被回显接口写坏了 —— 拿 9/26 的备份对比，**旧的那份也是 12 字符**，
是该平台在该 cookie 里的正常形态，不是损坏。

## 2. 一个"看着像故障"的正常现象

`renew_token.log` 从 12:47 起 20 分钟一行都没有，但循环是活的。
原因：P12-AJ 加的**静默快路径**（`renew_token.py:287`）——

```python
if d.get("expires_at", 0) - time.time() > RENEW_AHEAD_SEC:   # 还剩 >10 分钟
    _write_session_state("ok"); record_success(); return 0   # ← 这之前没有任何 log()
```

token 新鲜时它**故意不写日志**。所以"日志不动"= 健康；下一个整点续期实测按预测发生：

```
13:39:54 SKIP: token 未变化，无需写回
13:44:55 SKIP: token 未变化，无需写回
13:49:55 OK:  token 续期成功，已写回 token JSON
→ 新 expires_at 还剩 59 分钟 ✅
```

## 3. 两个真窟窿

### 窟窿一：心跳只在一条路径上写

`session_state.json` 原先只有**快路径**和 **401 分支**会写，而 `SKIP: token 未变化`
与 `OK: token 续期成功` 两条**真续期路径都不写**。于是每次续期窗口
（token 剩余 ≤10 分钟那 10 分钟）心跳必然变旧：

```
13:50 体检：循环心跳 = ❌ 疑似停摆（session_state.json 15.9 分钟前写过）   ← 假的
```

最坏 ~16 分钟 = 窗口 10 分钟 + 循环间隔 5 分钟。**这直接影响下面那条告警的阈值选择** ——
20 分钟的阈值离它太近。

**修法**：把心跳的语义定成"**循环跑到了**"（而不是"会话验证过了"），于是每一轮都写：

| 路径 | 写什么 | 含义 |
|---|---|---|
| 快路径（token 新鲜） | `"ok"` | 跑到 + 会话活着 |
| SKIP / OK / 浏览器续期成功 | `"ok"`（`main()` 统一补写。rc==0 才算） | 同上（echo 接口 200 就是活着） |
| 401 → 业务探针 | `"unauth"` / `"error"` | 真死 / 没法判断 |
| 撞验证码退避 | `"backoff"` | **跑到**，这轮没验证 |
| 抢不到会话锁（别人在重登） | `"locked"` | **跑到**，这轮没轮到 |

**关键约束**：`probe` 从此不止两种取值，所以读它的**三处**都必须
**只认 `"unauth"` 为死**（`check_bot_health.check_session_state`、
`sio_subscribe._token_stale`、体检探针）。按 `alive is False` 判的话，
一次验证码退避就会：巡检报"会话已失效" **+** SIO 把重连退避顶到 1 小时
—— 后者正是 P12-AJ 刚修掉的坑。

### 窟窿二：循环停摆无告警

- `check_session_state()`：文件超过 30 分钟就"不下结论"，**不告警**；
- `check_renew()`：只看 `FAIL:`/`SESSION_DEAD:`，而快路径**什么都不写**。

⇒ 循环死了/卡住了，日志里没有任何痕迹；只能等 token 到期、账号通道发不出去，
表现为"**群里突然不回话**"才被发现。

**修法**：新增心跳告警 `renew_loop`（挂在现有 `alert_token` 开关下，阈值
`RENEW_LOOP_STALE_MIN = 20` 分钟 = 连丢 4 轮）：

```
⚠️ 续期循环疑似停摆（心跳 N 分钟没更新，正常每 5 分钟一次）—— token 到期后将无法自动续期
```

两个刻意的取舍：
- **文件不存在不算停摆**（首次部署/换机没有心跳是正常的，那种情况由 `check_renew` 的 FAIL 兜）；
- 阈值取 20 而不是 10：正常最大间隔 ≈5~6 分钟，但要给"重启 + 首次重登"留余量。

## 4. 验收

### 4.1 决定性实验：真续期路径当场跑一遍（`tools/verify_renew_heartbeat.py`）

线上没法等 —— 一小时才有一次续期窗口，而且窗口结束后快路径会重新掩盖它。
所以做了个**受控的只读实验**：在本进程内把 `RENEW_AHEAD_SEC` 调到 `10**9`
（快路径判据 `expires_at - now > AHEAD` 立刻为假），于是**真的走到第 3 步**
（调只读接口比对 → token 没变 → 走 SKIP 分支）。不改生产文件、不写 token：

```
① 逼真实的「该续期了」分支：
  main() 返回 = 0
  新增日志     = ['2026-09-29 14:56:46 SKIP: token 未变化，无需写回']
  [SKIP 之后] 心跳 = 0.00 分钟前  {'alive': True, 'probe': 'ok'}
  → ✅：真续期路径**写了**心跳          ← 修之前这条路径不写，所以窗口里心跳会烂到 15.9 分钟
② 撞验证码退避分支：
  [退避之后] 心跳 = 0.00 分钟前  {'alive': False, 'probe': 'backoff'}
  → ✅：退避也留心跳，且 probe=backoff（不是 unauth → 不会被当会话失效）
③ 复位（跑真的 renew_token.py）：probe 回到 'ok' ✅
```

> 第一版探针我把阈值符号写反了（调成负数 = "永远新鲜"），于是 ① 什么都没验到、
> ② 根本没跑到，而输出仍然打了 ✅。**探针必须能发现自己没生效** ——
> 现在 ① 改成同时检查"日志里真的出现了 SKIP/OK 那行"，没走到分支就会 ❌。

### 4.2 其余

  三条路径都要留心跳、失败一轮**不许**把结论覆盖成 ok、`backoff`/`error`/`locked`
  都不算死、心跳过旧要判 `stale`、阈值必须大于实测的健康最坏值。
- 全量套件 0 失败（1267 收集）。
- 上线后 md5 逐文件一致；`check_health.log` 一直"巡检正常，无告警"（新告警没误报）；
  14:44/14:49 那次真续期窗口后心跳 1.5 分钟，`token.emergency` 不存在，`restarts=0`。
- 体检探针 `tools/probe_token_state.py`（新增，**不打印任何 token 内容**）：

  并能 `--probe` 当场跑一次业务探针验判别器。

## 5. 复盘

- **"日志不动"和"进程死了"长得一模一样**：静默快路径是为了少刷屏（P12-AJ 的
  1220 次 SKIP 噪声），但它把"健康"也变成了静默 —— 于是必须**另有一个能在日志之外
  表示"我还活着"的信号**（心跳文件），并且**每条路径都要写**。
- **心跳的语义要写死**："循环跑到了" ≠ "会话验证过了"。混在一起就会二选一：
  要么退避时假装活着，要么退避时被判停摆。拆开（`probe` 多几个取值）之后两条告警各管各的。
- **一个字段的取值一旦扩张，所有读者都要跟着改**：这次 `probe` 从 2 种变 4 种，
  三处读者都得从 `alive is False` 改成 `probe == "unauth"`。漏一处的后果不是报错，
  是**在特定场景下静默误判**（验证码退避 = SIO 退避 1 小时）。
- **阈值必须由实测的最坏值反推**：先量到"健康状态下 15.9 分钟"，才知道
  20 分钟的告警阈值其实很危险 —— 正确的动作是**修根因把最坏值压回 6 分钟**，
  而不是把阈值调到 30 分钟糊过去。
- **"验证脚本自己没生效"是最难发现的假阳性**：第一版实验阈值符号写反，
  输出照样一片 ✅。所以验证脚本必须内置"我确实走到了那条分支"的证据
  （这里是**日志里真的多了一行 SKIP**），否则它只是在复述我的假设。
