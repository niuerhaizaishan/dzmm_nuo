## 规则和命令

- 仅顶层茶水间、有效人设 `nuo`、`features.office=true` 时处理专用命令。
- `#允许潜规则`、`#拒绝潜规则`：本人修改个人开关，默认允许，持久保存；未设置过开关的现有成员及新成员均按允许处理，已有明确拒绝保持有效。发起者的开关只控制别人能否向其发起。
- `#潜规则状态`：个人开关、今日剩余次数、是否有会话。
- `#潜规则 @目标 [剧情方向]`：发送者是发起者。也支持工号 `#0001`、平台 UUID、唯一名称；名字包含空格时用双引号。显示名称由员工匹配接口唯一解析，不从近期聊天猜人。
- 引用对方本群消息发送 `#潜规则 [剧情方向]`：核验原消息 ID 和群归属，以实际作者为目标，不信任引用载荷里的作者、文字或嵌套引用。此模式全部参数作剧情方向，空参数自动选场景；机器人回复仍引用用户本次命令。原消息找不到时明确提示，不猜目标、不扣次数。
- 双方必须是本群非机器人、已入职，发起者 `rank_level` 严格高于目标。允许跨部门，部门不参与资格判定；游戏次数不是职级排序。
- `#潜规则继续 [方向]`（简写 `#继续 [方向]`，兼容 `＃继续`）：仅双方，重新读取成员和职级；最多续写三次。部门缺失或变化不影响续写资格。
- `#潜规则结束` 或 `#结束`（兼容全角 `＃`）：仅双方；拒绝开关也会结束本人参与的会话，取消未投递结果。
- 每个发起者按北京时间每天一次。首段发送前事务预占，确认成功后使用；续写不额外扣次。不使用游戏额度、商店次数或摸鱼币。
- 一人同时参与一场，不锁住整个群。开始及续写正文显示“会话短号｜发起者 × 目标”，每条回复显示本次指令作者和指令短号，用于区分多人回复并避开平台相同正文拦截。不同人员可同时存在多场会话；进程最多同时处理四个生成任务。
- 首段和续写正文以每段 400～600 个非空白字符为目标，完整的 200～399 字正文也接受；低于 200、超过 600、截断或不完整结尾时才修订，独立办公室剧情模板依据双方性别调整称谓及代词，未知用姓名。参考原场景的“人物→场景→方向→上下文”组织结构，写双方自愿、非露骨的互动；原 `/发骚` 提示词不改动。

跨部门不再拦截或发送拒绝提示。对方职级更高时：

> 胆子挺大呀，领导都敢点？小小糯替你把申请撤回了，快去努力升职～

同级提示：

> 工牌摆一起，谁也管不了谁呀～只能向职级比自己低的成员发起哦。

## 计时、取消与失败恢复

首段成功后 300 秒无有效互动自动结束。续写成功后重新计时；生成中有独立的 120 秒持久化处理截止时间，模型调用总预算 45 秒、最多三次生成/修订、外层等待 50 秒，不会无限挂起。

普通聊天、无权限操作、查询状态均不刷新计时。续写生成失败恢复原空闲截止时间。拒绝、结束、关闭功能、旧 operation 的迟到结果不能复活会话。

生成前、准备发送时、等待账号发送锁结束后检查许可与会话状态。消息一旦已经交给平台则无法保证撤回；用户在网络等待期间拒绝，会关闭会话且不允许后续续写，但已投递内容不会自动删除。

SQLite 事务负责参与者互斥和每日额度；“群＋原指令消息 ID”负责去重。重启后读持久化截止时间处理旧会话；正在生成但中断的任务到期释放未发送首段的预占额度。

长消息整条走账号 Socket.IO，`content.reference` 引用各自的原指令。Outbox 保存完整正文、引用、单条标记，使用独立 `office_reply` 类型，禁止被普通文本重试器重放。最终发送 guard 在 Socket.IO 动作锁内运行，避免排队期间的拒绝被绕过。ACK 后读回核对消息 ID、作者、全文与引用；引用的原指令 ID、原指令作者及原文必须一致，防止多人并发时错误绑定。正文及标识整合为一个自然段，不含换行、空行；故事正文单独校验 200～600 字（400～600 为目标），不截断，标识不写入剧情历史。

账号未连接或可重试的明确未投递：保留原文、最多尝试三次，不重新生成、不拆分。平台明确拒绝重复内容时只尝试一次，引用原指令告知失败；未投递首段释放额度，续写失败恢复原会话及截止时间。全部明确失败时释放未发送首段额度；网络超时、ACK 不明或读回不符：保留待核对状态和额度，禁止盲目重发。原生引用是否被真实茶水间完整保留尚待联调，不能将模拟测试当作线上验证。

超时通知引用最后一条有效指令。通知发送前持久领取，结果不明不重复发送；生成超时/投递待核对使用不同文案，不误报为纯空闲超时。

## 已接通的员工接口

名称、工号解析使用 `POST /users/match`，只接受唯一匹配结果；`ambiguous` 要求重新指定，不任选候选。平台 UUID 可直接用于后续成员及职级核验。

职级读取使用现有 `GET /users/{platform_id}/game-quota`，模式为 `game_quota`。此接口提供身份和职级名，没有部门、职级排序或性别。适配器只读取资料，不消耗游戏次数；额度大小、无限次数标记及剩余次数都不参与职级比较。没有假定 `/profile` 已存在。

用户明确确认从低到高的顺序：实习生 → 正式员工 → 小组长 → 副主管 → 主管 → 部门副经理 → 部门经理 → 部门副总监 → 部门总监 → 公司负责人 → 核心董事会。映射为 1～11；未知职级、无效排序配置、UID 不符时拒绝，不扣次数。

服务端配置（密钥只保存在受保护环境文件中）：

```text
DZMM_INTEGRATION_BASE_URL=https://49.234.20.159/api/integration
DZMM_INTEGRATION_API_KEY=<server-only-key>
DZMM_EMPLOYEE_PROFILE_PATH=/users/{platform_id}/game-quota
DZMM_EMPLOYEE_PROFILE_MODE=game_quota
DZMM_EMPLOYEE_RANK_ORDER=<上述 11 档职级的 JSON 数组>
```

部门可缺失，允许跨部门。性别优先使用明确的接口资料；当前接口未返回时沿用原场景的档案/平台资料识别，不写回、不从昵称猜测；未知使用姓名或中性称呼，不默认上级男性、下级女性。

成员仍须在本群且不是机器人。茶水间专用成员查询上限提高到 2000；达到上限或返回后续页标记时拒绝开始，避免使用截断列表。其他管理功能保留原默认查询上限。

HTTPS 校验证书，禁止重定向携带密钥；异常只记录类型。进程内每分钟最多 45 次请求，服务端 429 仍为最终限制。服务端 `.env` 权限为 0600，集成设置仅传给主机器人服务。

## 数据与归档

- 玩法：`data/office.db`（可通过 `DZMM_OFFICE_DB` 指定），个人开关、原指令去重、额度、会话、生成全文、引用和通知记录。
- 群消息：沿用 `data/chat_archive.db`（可通过 `DZMM_CHAT_ARCHIVE_DB` 指定），归档开关仍为 `DZMM_CHAT_ARCHIVE=on`。代码扩展认证群及茶水间的允许范围，不修改现有开关。
- 旧库在下一次写入连接时事务重建单群 CHECK，复制并核对记录数，重建索引，失败回滚。生产切换已在一致性备份后完成迁移，24,774 条旧记录逐条摘要核对保留；真实茶水间消息持续入库。
- 所有收到的消息先归档再做命令/自回声过滤，群＋消息 ID 去重；图片等保留原始元数据，不下载附件。
- 后台 `/messages` 增加群选择，默认仍显示认证群，分页、筛选、发送者链接保持所选群。个人故事/画像等证据读取仍限原认证群，不因茶水间入库而自动扩大范围。
- 历史导入沿用 `runtime.chat_archive.import_jsonl(..., group_id=TEA_CID)`，只写归档、不执行历史指令。历史平台消息的全量抓取与补漏没有在本轮执行；实时采集也不等于已具备完整历史。
