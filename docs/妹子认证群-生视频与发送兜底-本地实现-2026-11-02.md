## 用法与配置

- `/生视频 提示词`：生成一个 6 秒、480p 短视频，文生视频使用 1:1。
- 回复本群静态图片，发送 `/生视频 动起来，镜头慢慢推进`：图生视频，保持原图构图比例。
- `/生视频` 显示帮助；接受半角和全角斜杠，无需额外 @。
- 立即告知前面还有多少个视频排队、多少个正在处理。视频单独一个生成/发送槽位，最多等待 4 个；每人一个在途视频。
- 视频原生回复最初的 `/生视频` 指令，核验编号、发起人和原始正文；不引用源图作为结果上下文。
- 生成视频可用现有 `/保存` 收录到图集。

`videogen` 默认关闭，必须在妹子认证群显式开启，另受 `slash_cmds` 总闸约束；其他群不生成。模板 `config.example.json` 示范开启，不会修改服务器运行配置。提示词最长 2000 字，冷却默认 60 秒，等待上限 300 秒（可调 30～600 秒）。冷却与生图共用任务表，同一用户刚提交生图/视频后也受保护。

复用 `XAI_API_KEY`、`DZMM_IMAGEGEN_DB` 和 `DZMM_IMAGEGEN_PUBLIC_BASE`，无需第二个 key。机器人与图集 API 必须共享同一个任务数据库，运行镜像需要 `requirements.txt` 中的 PyAV 解码依赖。

## xAI 与结果持久化

按官方 [视频生成文档](https://docs.x.ai/developers/model-capabilities/video/generation) 和 [图生视频文档](https://docs.x.ai/developers/model-capabilities/video/image-to-video) 接入模型 `grok-imagine-video-1.5`：

1. `POST /v1/videos/generations`，只提交一次计费请求。
2. 图生视频的 REST 参数是 `image: {url: "data:image/...;base64,..."}`；不是 SDK 形参 `image_url`。
3. 保存 `request_id`，轮询 `GET /v1/videos/{request_id}`，处理 `pending`、`done` 和 `failed`。
4. `done` 后立即下载临时 MP4，限制 50 MB，核验视频容器及可解码首帧，再保存字节。下载请求不带 API key，不跟随重定向。
5. 使用既有随机 token 地址 `/api/gallery/generated/{token}`，按真实 `video/mp4` MIME 提供 HEAD/GET 和字节 Range；不加入公开图集列表。

引用必须回查群历史，不能信任推送携带的图片 URL。引用文字、视频、跨群原图、错作者指令、原图核验失败均在付费请求前拒绝。生成中关闭功能或用户退出群后不会发送，已得到的 MP4 保留。

任务去重、冷却、原指令快照、结果字节和平台消息编号均持久化。图片与视频恢复状态按 `mode` 分隔，懒启动服务不会误标另一类正在运行的任务。取消/超时/重启不自动重新提交 xAI；已提交的远程编号保留，但本版不自动续接轮询。明确发送拒绝可由运维重放同一原指令发送已保存结果，发送不明确则必须先核对群历史。

## 发送与兜底

图片：优先小小糯原生引用发送，账号明确拒绝或断线时先上传到平台存储，再经官方 `sendPhoto` 发送。账号或官方发送结果不明确时停止切换/重试。平台上传需要有效账号 HTTP 会话。官方 Bot 未确认支持原生引用，因此兜底图片不保证原生引用；正常账号发送保留严格引用。

视频：账号 Socket.IO 发送原生 `video`，含 `status=ready`、`videoUrl` 和原始指令引用，回读确认发信人、类型及引用后才记录送达。平台目前公开 Bot 文档未提供视频接口，不能凭 Telegram 兼容命名假设存在 `sendVideo`。账号视频通道不可用时在计费前明确提示；生成后断线则保留 MP4 并说明未发送，不退化为群里的一条视频链接。
