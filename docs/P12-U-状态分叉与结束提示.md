工作线程把"发骚进行中"写进了旧的 `state.json`，主流程读的是 SQLite —— 两边互相看不见。

## 三、真因（有线上实证）

1. `runtime/store.py` 建连接时用的是 sqlite3 的默认参数
   `check_same_thread=True`：**连接只能被创建它的那个线程使用**。
2. 而 `Store` 是**模块级单例**（`state_store._store`），bot 里又有大量状态写在
   `asyncio.to_thread(...)` 的**工作线程**里：发骚 `scene()`、剧情/投票/公演状态机、
   `sync_profiles()`、档案写回……
3. 工作线程一碰这个连接就抛
   `sqlite3.ProgrammingError: SQLite objects created in a thread can only be used in that same thread`，
   而 `state_store` 把那句话**吞掉**并退回 JSON 文件：

```
sqlite：主线程读写的"一半"（last_id、发情值、指令链里的状态）
state.json：工作线程读写的"另一半"（发骚会话、档案、玩法状态机）
```

4. 于是：`scene()` 在工作线程里把"发骚 active + 历史"写进 `state.json`；
   主线程的收尾分支读 SQLite ⇒ 读不到 ⇒ **判定"没有进行中的发骚" ⇒ 静默**。
   同一个原因还解释了 `/继续` 为什么正常：`continue_last` 本身也在工作线程里，
   它读的也是 `state.json` —— 自洽，所以看起来没问题。

**线上实证**（容器内探针，`tools/probe_store_split.py`）：

```
state.json 15:39:48（正是 /发骚 那一刻）
  本群 fasao：active=True full='糯糯大嘴巴抽晴天' history=1
sqlite 里的本群：
  fasao = None                       ← 收尾分支读的就是这个
两个后端分叉：只在JSON=['fasao']，只在sqlite=[last_id/发情值/msg_count/...]
```

5. 修好并并回数据后，主线程立刻"看见"了那场发骚：

```
15:54:49 ⏱️ [f4ec4c21] 发骚超时自动结束     ← 修复前它永远看不到，不会超时
```
（那条是 15 分钟无互动的自动收尾；并回数据后主线程才读得到。）

## 四、修了什么

| # | 改动 | 说明 |
| --- | --- | --- |
| 1 | `runtime/store.py`：`check_same_thread=False` + **一把可重入锁** | 连接可被任意线程使用；sqlite3 连接对象本身不是线程安全的，所以访问全部串行化。跨进程并发仍由 WAL + `busy_timeout` 兜 |
| 2 | `state_store.py`：**不再静默降级** | 所有"退回 JSON"的 except 都改成**吼一次**（每个原因只喊一遍）：`⚠️ state_store: sqlite 不可用，已退回 JSON 文件 —— …请立即排查`。这次它藏了两个小时，就是被静默吞掉的 |
| 3 | `tools/merge_json_into_store.py`：把 JSON 那一半并回 SQLite | 状态机键按"active / 内嵌时间戳更新"判定，且**只认一小时内的**（更早的过期状态不并 —— 否则会出现"群里没在发骚却被锁住"）；其他键只补缺失，冲突只报告；落库前自动备份 |
| 4 | **`/结束` 兜底提示**（你选的） | 通用停止词（`/结束` `/停止` `/停下` `/终止`）在所有收尾分支都没接住时，回一句「现在没有进行中的玩法。」；`/剧情结束`、`/调教结束` 这类**点名的**照旧归各自功能（功能关了就还是静默） |
| 5 | 回归测试 +3 | `Store` 跨线程读写、`state_store` 跨线程往返（并断言零降级告警）、停止词提示分支的位置与措辞 |

顺带修掉一条**飘忽的测试**：`test_male/female_target...` 断言"随机羞辱词库"，
但"拉满"那条用的是 `HARD_INSULT_PROB`（0.75）而不是 `RANDOM_INSULT_PROB`，
所以会 25% 概率随机挂 —— 现在两个概率都压到 1.0，连跑 6 次全绿。
