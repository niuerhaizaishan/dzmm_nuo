# P12-BD：让上班群的**若瑾说话更像人**（方案 · 待拍板）

> 屋主 2026-09-30："上班群的若瑾，能有办法让她说话更像人一些吗？给我方案先"
> 随后点题："**就是说话有点太像机器人了，就和工具熊每次都要问要不要调酒一样的询问一样。主要是这个问题。**"

## 1. 真问题：她**每句都在把话头递回去**

"要不要我给你调杯酒"那种机器味的本质不是长短，是**每句话都在要对方产出下一轮**
（提问、派活、或者贴一张指令菜单）。真人聊天大多数时候是**说完就停**。

取上班群最近 600 条（`tools/probe_solicit.py`，排除其他 bot）：

| 收尾类型 | **若瑾**（15 条） | **真人**（515 条） |
|---|---|---|
| 提问收尾 | 0% | 3% |
| **派活收尾**（选一个/我等着/说清楚/换个说法再来…） | **67%** | 2% |
| **指令菜单**（/"xxx" 形式的操作提示） | **27%** | 10% |
| **陈述收尾（说完就停）** | **13%** | **85%** |
| **递话率（提问+派活）** | **67%** | **6%** |

她这 15 条的末尾原文（`probe_solicit.py` 打印）：

```
…要么好好说话，要么就闭嘴看着别人聊。选一个，我等着。      ← 派活
…坐下，好好说话，我听着！                                  ← 派活
…想让我高兴，换个说法再来❤️                                ← 派活
…想让我理你，先把话说明白❤️                                ← 派活
…把你那点心思也收一收！！                                  ← 派活
…想接话发 /命令 xxx，收尾发 /调教结束。                     ← 指令菜单
…（加不加「命令」都可以）～30秒没人我就自己继续啦～            ← 指令菜单（重复 3 次）
…、🔥发言排行，也能陪你聊天～发 /说明 看全部功能～            ← 欢迎语里的功能菜单（重复 2 次）
```

## 2. 四个来源（都能落到具体位置）

| # | 来源 | 位置 | 说明 |
|---|---|---|---|
| ① | **硬编码的参与提示，绕过话术表** | `bot.py:3641` `reply += "\n\n" + DJ_PARTICIPATE_HINT` | 用的是 `runtime/diaojiao.py:37` 那句**软糯原文**（"想参与的**姐妹**也来玩呀～…（加不加「命令」都可以）～30秒没人我就自己继续啦～"）。若瑾的 `dj_hint` 覆盖**在这条路上不生效** ⇒ 漏旧人设 + 每轮重复刷同一条 + 带倒计时（"30秒没人我就…"= 明摆着是机器人在等输入） |
| ② | **人设自己的例子全是"派活"** | `personas.py` `RUOJIN_EXTRA` §属性 | 例："谁准你吩咐我了？""把刚才那句收回去。""想清楚再说。" —— **示例教出来的就是"要对方回话"**，模型照着学 |
| ③ | **欢迎语是功能菜单** | `bot.py:1236` `WELCOME_TEXT`（"+ 【群简介】若瑾会 🔮算命、📇查档案…发 /说明 看全部功能～"） | 每来一个新人就贴一次"我能做什么"清单 = 工具熊式招揽。而且它是**硬编码软糯版**（"…群里的小秘书～♡"），人设里写着"不是小秘书" |
| ④ | **"主动权得一直在你手里"被执行成"每句要你表态"** | `RUOJIN_EXTRA` §属性/§活人气 | S 的压迫感本该靠**陈述句与命令句本身**，现在靠"我等着/我听着/换句话再来"这些**等回应**的句子 |

次要问题（上一版量过，仍要一起收，但不是主因）：中位长度 116 字 vs 真人 7 字、
空行分段 93% vs 7%、❤️ 80% vs 1%（`_ensure_decor` 确定性补的）。

## 3. 方案

### 第一批 · 掐掉"递话/菜单"的来源（半天，低风险，直接对题）

| # | 改动 | 预期 |
|---|---|---|
| a | `bot.py:3641` 改走话术表（`_dj_phrase(cid, "dj_hint", DJ_PARTICIPATE_HINT)`），并且**每局只粘一次**（第二轮起不再粘） | 软糯口吻不再漏；不再刷同一条；倒计时提示只出现一次 |
| b | 欢迎语去掉功能菜单，改成**一句话**（功能清单只留给 `/说明`）；`WELCOME_TEXT` 挪进话术表，给若瑾一套（不撒 ♡、不叫姐姐、不提"小秘书"） | 新人欢迎从"菜单"变"打招呼" |
| c | `RUOJIN_EXTRA` 里那三句"派活"示例**换成"说完就停"的**（"谁准你吩咐我了。"→"我记下了。" 这类），并新增硬规则：**不要以"要不要/想不想…？"收尾**；不要让对方"选一个/说清楚/换句话再来"；**不要贴指令菜单**（玩法第一轮除外）；不写倒计时 | 递话率的主要来源被拆 |
| d | 加一节"**说完就停**"：一次说一件事；S 的压迫感用陈述句/命令句，不靠"我等着""我听着"；被搭话就答完即止（**不等他接话**） | 收尾回到陈述 |

### 第二批 · 兜底 + 语料（一天）

| # | 改动 | 说明 |
|---|---|---|
| e | **收尾检测 + 一次重写**：`_solicit_tail(text)` 命中（`要不要`/`选一个`/`我等着`/`我听着`/`换个说法`/`发 /xxx`/`30秒`）→ 让模型按"别要回应、说完就停"**重写一次**；再命中就**删掉最后那句纯招揽句**。按群开关，默认关，只作用于 @ 闲聊路 | 提示词管不住的那部分用代码兜（同 `_ensure_decor` 的思路），但**先重写、后删句**，避免把话说残 |
| f | few-shot 换成**上班群真人语料**：10~12 组「别人说 → 她怎么回」，全部 7~20 字、"说完就停" | 示例决定输出分布（P12-AL 的教训：光写规则没用） |
| g | 顺手收次要问题：`chat_decor` 概率化（`❤️:0.3`）、`_humanize_chat()` 收空行（`\n\n`→`\n`）、`chat.max_chars` 分档（闲聊 ≤40 字 / 正经提问 ≤150 字） | 长度 116→40、空行 93%→0%、❤️ 80%→30% |

### 第三批 · 可选（产品决策）

- 主动冒话（`devil_roast`/`devil_cold`，现在全关）：先加"每天上限"参数（建议 5 条/天）+ 冷却 + 静默时段；
- 早/午/晚问候（现在全关）：要开就改成**一句话**、不带模板感。

## 5. 明确不做

- **不动玩法正文**（羞辱/发骚/调教/场景的文字本身）—— 那部分她最不出戏；这次只改**流程提示语**与**闲聊收尾**；
- **不把"像人"做成"敷衍"**：正经提问仍要说清（P12-AU 的教训）；
- 不关 ❤️（屋主 P12-AH 点名要的），只降密度。

## 6. 需要拍板

1. **收尾兜底要不要做**（第二批 e）：能兜住"提示词又没管住"的情况，代价是命中时多一次模型调用（+1~2s）；
2. ❤️ 密度：1/3 条？1/5 条？只在给糖/收尾时撒？
3. 主动冒话要不要开、一天几条（建议 ≤5）；
4. 顺带把长度/空行/装饰一起收（第二批 g）还是这次只解决"递话"？

# 附：第二个问题 —— 她读的是**全群记录**，不是"你和她"（P12-BE）

> 屋主 2026-09-30（追加）："**我如果我回复她，她会读取之前很多人的记录，一一批判回复。
> 能设置成那种，我回复她，她只会读取我之前的和她的记录，来进行回复嘛**"

## A1. 现在长什么样（把真送进模型的上下文原样打出来）

`tools/probe_ctx_scope.py`（上班群，此刻）：

```
上下文 16 条（reply.context_msgs 默认 20）
  工具熊 Jr.   | ✧ 2026-09-30 运势 ✧ ...        ← 别的 bot
  ROI         | /luck
  工具熊 Jr.   | ✧ 2026-09-30 运势 ✧ ...
  用户0820      | /luck
  工具熊 Jr.   | ✧ 2026-09-30 运势 ✧ ...
  呱呱💗        | /luck
  工具熊 Jr.   | ✧ 2026-09-30 运势 ✧ ...
  晴天☀️       | @若瑾 你是机器人嘛
  我           | 🤖 机器人？你见过哪个机器人会嫌你问得没水平！...
  晴天☀️       | /羞辱 roi，狠狠羞辱这个男同
  我           | 🤖 查不到这个人，骂谁去。
  ...
不同说话人 5 个：['工具熊 Jr.', 'ROI', '用户0820', '呱呱💗', '晴天☀️']
她自己只占 3 条 / 别人占 13 条
```

**根因**：她答话时的上下文是 `_TURNS[cid]` —— 一份**全群滚动记录**（进来每个人的话 +
别的 bot 的话 + 她自己的话，`bot.py:391`），@ 分支整块取最近 `reply.context_msgs` 条
喂给模型（`bot.py:3936`）；记忆注入 `_retrieve_memory(cid, q)` 也是**按问题在全群记忆里检索**
（`bot.py:3971`），`{pending}` 那一行还可能列出好几个人的事。所以：

- 你回她一句，模型看到的是"刚刚谁在群里说了什么"⇒ 顺手把别人也点评了（"一一批判"）；
- 上下文里 **别的 bot 的刷屏**（工具熊的 /luck 运势卡）占了很大比例，模型会当成"群友发言"来回应。

## A2. 方案

| # | 改动 | 说明 |
|---|---|---|
| a | **新增按群参数 `reply.ctx_mode`**：`0`=全群（现状，默认，零回归）／`1`=**双边**（她 + 当前跟她说话的那个人）／`2`=双边（**仅屋主**，其他人照旧全群） | 上班群设 1 或 2，由你定 |
| b | `_remember_turn()` 记下 **uid**（现在只记名字 `who`，改名就认错人）→ `_recent_turns(cid, n, only_uid=…)` 只留"她"和"这个人" | 双边过滤靠它，改名也不怕 |
| c | **别的 bot 的消息不进上下文**（工具熊/总监事这类：按 isBot 标识 + 名字里带「bot」兜底） | 顺手治掉上下文里大量 `/luck` 刷屏 |
| d | **记忆与 `{pending}` 按人过滤**：双边模式下只留"提到当前这个人 / 他托付的事"的条目，其余不注入 | 这是"一一批判别人记录"的另一半来源 |
| e | 提示词补一条（`AT_FRAME_PROMPT` 延伸）：**"他在回你的话，就只跟他一个人说；不要点评群里其他人、不要逐条念别人的记录（除非他问）"** | 规则 + 上下文双管 |

引用的那条消息（右键回复引用的原文）在双边模式下**照旧带上** —— 那是当前这段对话的一部分。

## A3. 验收

- `tools/probe_ctx_scope.py`：上下文里的**不同说话人数 5 → 1**、别的 bot 条数 → 0；
- 生成侧 A/B（同一句输入，全群 ctx vs 双边 ctx）：统计回复里出现的**其他成员名个数**
  （`tools/probe_mention_spread.py` 已有的口径），目标 ≤1；
- 单测：`_recent_turns` 双边过滤（含改名场景）、别的 bot 过滤、记忆按人过滤、
  `ctx_mode=0` 时行为与今天逐字一致（零回归）。

## A4. 这条和第一批的关系

两条都指向同一件事：**她现在是"群播报员"，你要的是"跟你一个人说话的人"**。
- P12-BD 第一批治"每句都要你回话"；
- P12-BE 治"她看的是全群、答的也是全群"。

两条加起来她才像"在群里跟你聊天的人"，而不是"读着公告板念稿的客服"。
建议**同一次上线**（都是 @ 闲聊那条路上的改动，回归面一致，一次验完）。

# 上线记录（2026-09-30 夜，屋主"全部"之后的第一批）

## 1. 落了哪些

| 计划项 | 落点 | 说明 |
|---|---|---|
| 第一批 **a** 参与提示 | `bot.py`（`/命令` 分支） | **删掉**每轮拼 `DJ_PARTICIPATE_HINT` 那一行。两个毛病：① 那是 `runtime/diaojiao.py` 的**硬编码软糯原文**，绕过话术表 ⇒ 若瑾的 `dj_hint` 在这条路上不生效、每轮漏"姐妹们…～"；② 每轮重复同一条 + 带倒计时（"30秒没人我就…"）= 明摆着的"我在等输入"。开场那次由 `start_diaojiao()` 走 `_dj_hint(cid)` 带，目标应了 `dj_replied` 再给一次 ⇒ **每局只出现一次**。 |
| 第一批 **b** 欢迎语 | `personas.py` `RUOJIN_PHRASES["welcome_text_plain"]` + `bot.py` `_welcome_of()` | 欢迎语改为**先问话术表**（`welcome_text` / `welcome_text_plain`），没写 key 的群逐字用常量。若瑾那份是**打招呼**，不是功能菜单（原中性常量带一整行【群简介】玩法清单，且列了她没开的算命/投票/骰子）。 |
| 第一批 **c/d** 人设 | `personas.py` `RUOJIN_EXTRA` | ① 三句"派活"示例（"谁准你吩咐我了？""把刚才那句收回去。""想清楚再说。"）换成**陈述式挡回**（"不给。""这话我不接。""我当你没说。"）；② 新增 **▍说完就停** 一节：黑名单点名写（反问要回应 / 派活 / 指令菜单 / 倒计时）+ 自检句；③ 长度口径改**分场合**：闲聊 20~60 字、正经问答一百到三百来字、玩法正文照旧。 |
| 第二批 **g** 装饰概率 | `runtime/features.py` + `bot.py` | 新增 `chat.decor_prob`（1.0）/ `chat.bang_prob`（1.0）—— `_ensure_decor` 从"确定性"改为按概率。**默认 1.0 = 今天的行为**，只有配了才变。 |
| 第二批 **g** 符号密度（**真正的杠杆**） | `personas.py` `RUOJIN_EXTRA` 两处 | 把"**每条都带 ❤️**／条条上感叹号"改成"**大约三条里一条**／两三条里至少一处"，并给一个**不撒符号**的例子。实测：改前离线 93% 带 ❤️，改后 33%（目标 ≤35%）。⚠️ 提示词写了"每条都带"，`chat.decor_prob` 就是摆设 —— 概率只管代码**补**的那一个，管不住模型自己写的。 |
| 第二批 **g** 排版 | `runtime/text.py` `_humanize_chat()` + `chat.humanize`（0） | 空行折单换行、最多 5 行（**保留最后一行**，免得截成半句）；只动版式、一个字不改。 |
| 第二批 **g** 长度 | `bot.py` `_apply_frame_length()` + `chat.frame_length`（""） | **整行替换**收尾块里的【写多长】，省得"2~6 句、100~300 字起步"这条通用口径在闲聊里变成"每句都写小作文"。 |

一处**刻意偏离原方案**：g 里写的是 `chat.max_chars`（硬截断，闲聊 ≤40 字 / 正经 ≤150 字），
实际做成 `chat.frame_length`（**自然语言口径，换掉提示词那一行，不截断正文**）。
理由：硬截断会把话说半截（P12-AU 的教训就是"提示词把人说短了"），而口径交给模型
自己按内容取舍更稳，也便于按群微调。

## 2. 对**所有群**生效的一处行为变化（要说清）

**参与提示不再每轮重复**（第一批 a）。认证群原来每条 `/命令` 尾巴都挂着那句
"想参与的姐妹也来玩呀～…30秒没人我就自己继续啦～"，现在只在开场出现一次。
这是**有意的**（重复同一条 + 倒计时正是被点名的机器味），但它确实改了认证群的行为 ——
如果屋主希望认证群保持每轮提示，改法是把那句挪回话术表并按群开关控制（一行的事）。

## 3. 参数与配置

新增四个按群可调参数（`runtime/features.py`，页面/配置均可改）：

```
chat.decor_prob   1.0    → 上班群 0.3
chat.bang_prob    1.0    → 上班群 0.5
chat.humanize     0      → 上班群 1
chat.frame_length ""     → 上班群「长度照真人来：一两句就够，20~60 字、最多 4 行…」
```

落配置用 `tools/set_chat_tuning.py`（`--apply` 才写；`--reset` 撤回）：

```bash
docker exec dzmm-bot python tools/set_chat_tuning.py            # dry-run
docker exec dzmm-bot python tools/set_chat_tuning.py --apply
```

⚠️ **必须先 build + up 再跑它**：参数登记表（`PARAMS`）是 `import` 时建的，
**热加载不会重建**（`hotload` 只刷 features/tuning 的**覆盖值**、话术、提示词）。
新参数在旧进程里是"未知 key"，`set_overrides()` 会直接抛 —— 这是刻意的 fail loud。

## 4. 验收

### 4.1 实测（上线后，`tools/probe_bd_ab.py`，2026-09-30 21:14）

同一批**真实 @ 她的输入**（临屿/pingu/晴天 的 5 句），各采样 3 次 = 15 条/组；
两组都是**现人设**（含"说完就停"），差别只在长度口径那一行：

| 指标 | 目标 | **A 旧口径**（原【写多长】） | **B 线上口径** | 改动前线上 |
|---|---|---|---|---|
| 递话率（提问+派活） | ≤15% | 33% | **20%** | 67% |
| 陈述收尾 | ≥70% | 67% | **80% ✅** | 13% |
| 中位长度 | ≤45 字 | 112 字 | **19 字 ✅** | 116 字 |
| 空行分段 | 0% | 0% | **0% ✅** | 93% |
| ❤️ 占比 | ≤35% | 33% | **33% ✅** | 80% |

结论：**长度口径那一行是主因**（112 → 19 字、递话 33% → 20%）；
❤️ 的下降**不是** `chat.decor_prob` 的功劳（那条只管网民补的那一个）——
是**人设里"每条都带 ❤️"改成"大约三条里一条"**才降下来的：
