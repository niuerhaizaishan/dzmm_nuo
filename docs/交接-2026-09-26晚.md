## 明天第一件事：把"收消息"改成官方 Webhook

**已经查清的事实**（官方文档重新渲染过）：

- 官方收消息**只有 Webhook 一条路**，没有 `getUpdates` 那种长轮询 ✗；
- Webhook URL 在 **Bot 详情页**填；校验头是 `X-Telegram-Bot-Api-Secret-Token`；
  payload 是 Telegram 风格（`update.message.chat.id` / `.text`）；
- 平台硬要求：**公网 HTTPS**，会阻断 localhost / 内网 IP / 解析失败；
- 发消息**已经**走官方 Bot API（`/api/bot/send-message`，日志里的 `bot_ok`），不用改；
- ⚠️ 即使收消息走 Webhook，**侧车账号也退不掉**：档案/成员/筛查踢人/图片/私聊仍靠它。

**卡点**：这台机器没有公网 HTTPS 入口 —— 没 80/443、没 nginx/caddy/certbot、没自己的域名。

**两条路（等屋主定）**：

- **A（推荐）**：屋主有域名 → DNS 加 A 记录 `bot` → `47.237.152.187`；
  安全组放行 **TCP 443 + 80**（来源 `0.0.0.0/0`，平台的出口 IP 不固定）。
  我：装 Caddy 自动签证书（只暴露 `/bot/webhook`）+ 写接收端（校验 Secret、按
  `message_id` 去重、喂进现有队列、Socket.IO 留兜底）+ 本地模拟 payload 测通。
- **B（没域名时最省事）**：ngrok 免费固定域名（不需要域名/证书/开端口），
  屋主给 authtoken + 域名，我装 ngrok 常驻 + 同样的接收端。

两件事需要屋主回答：**① 有没有域名（哪家的、叫什么）② 走 A 还是 B**。
