# Rose 管理确认

仅适用于 Rose 房间 `4a56be71-9ca6-4785-b45f-18725d187f1a`。新增功能开关为
`rose_moderation`，新环境默认关闭。2026-10-12 已部署，并仅在 Rose 开启。
已只读核验执行账号的群管理员权限、账号连接、容器文件版本及原有功能开关。
未发送群测试消息，未实际测试撤回或踢出。

## 使用方法

1. 群管理员回复原消息发送 `/阿瓦达啃大瓜`，生成带目标昵称、用户编号、消息摘要和发起时间的确认提示。
2. 任意当前群管理员回复该提示发送 `/确认`，撤回原消息并踢出原发送者；回复 `/取消` 只取消该任务。
3. 不回复消息直接发送 `/确认`：仅一条待处理时直接执行；多条时先生成摘要汇总，再次 `/确认` 或回复汇总任意一页 `/确认` 执行该汇总。
4. 直接 `/取消` 取消全部尚未执行的任务和汇总；回复汇总 `/取消` 只取消汇总中尚未执行的任务。

汇总是固定快照：后续新增任务不纳入，已经单独取消或执行的任务跳过。
同一用户的多条消息逐条撤回，全部撤回得到确认后只踢出一次。某一条撤回失败，
该用户本批次不踢出；其他用户继续处理。成功原文保持用户要求，批量操作另报完成数量及失败详情。

## 权限与发送

操作人权限来自平台 `chatroom.getMembers` 的 `metadata.role` 和
`chat.listAll` 的 `creatorId`，不用项目里的固定屋主名单。发起和执行时重新检查权限，
保护群主、管理员、机器人。角色未知、成员列表不完整或原消息无法核验时不执行。

提示及结果一律走当前账号连接（侧车账号「小小糯～」），与撤回、踢出是**同一个
执行者**——屋主 2026-10-12 明确不许提示走本群 Bot（薇丝）导致身份劈叉。
只绑定明确成功回执中的消息编号，回复普通聊天、其他群提示或伪造摘要不能确认任务。
提示发送结果不明时不自动重发，也不将任务加入可执行队列；管理员可再次回复原消息发起提示。
不修改 Rose 现有人设或机器人昵称。

删除通过现有账号 Socket.IO 连接的 `message:delete`（载荷 `{chatroomId, messageId}`，
ACK `success: true` 才算成；2026-10-12 实测：旧协议 `message:recall` 只能撤自己的消息，
删别人的会被拒 `CANNOT_RECALL`，且连接必须先 `message:join-room` 进房间）。
踢出通过账号 `groupChat.removeMember`，并重新读取完整成员列表确认目标已不在群中。
执行账号必须有 Rose 管理权限。上线时已确认该权限具备；真实删除与踢出的回执仍待实际管理员操作验证。
部署检查曾发现 HTTP 模式的 Socket namespace 握手超时，已增加兼容回退：
超时后携带账号 Cookie，改用普通 WebSocket 握手。该路径已只读验证能收到加入通知与自然消息。

## 持久化与异常

任务不设有效期，不做定时清理，保存在忽略提交的 `data/rose_moderation.db`。
记录原消息编号、原发送者、消息时间、昵称快照、摘要、发起人、确认人、提示编号、
汇总范围及执行结果。仅记录涉及管理任务的信息，不采集 Rose 全量聊天。

任务和指令通过数据库原子领取防重复。重启保留待确认任务和汇总；已经进入执行状态的任务
不会重新执行。超时、断线、进程中断或部分成功时保留实际进度，需人工核查，禁止自动重试管理动作。
已完成及结果不明的原消息不会通过重复发起再次处理。
已取消任务可以显式重新发起，产生新的确认提示；回复旧提示不会处理新任务。

初次核验优先使用引用携带的原消息时间；没有时间时只在最近 500 条消息内查找。
过旧消息若无法核验，会明确拒绝。
已创建任务保留原消息时间，执行时按该时间附近重新读取，不受任务存放时长影响。
若平台消息已删除、列表被分页截断或读取失败，同样停止处理。
