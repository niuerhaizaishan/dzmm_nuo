## 2. 两组证据对不上 —— 这就是关键

| 来源 | 它说的话 |
|---|---|
| `renew_token.log` | "**refresh_token 失效（未授权）**" ×460 |
| `monitor_recover.log`（宿主，09-07 起常驻） | "**首页=418**" —— 三周累计 **6570 次**，一直是这样 |

而坏了几小时之后，**同一份 cookie** 又能成功续期（`OK: token 续期成功`）——
中间没有任何登录动作。⇒ **那几小时会话根本没死，是平台把我们挡在风控墙（418 验证码墙）外面**
（`未授权` 是墙挡出来的），墙解除后同一个 token 自然又能用。

今天（12:23~13:27）是**另一种**：墙在 13:26 已经解除（首页 200），但会话确实死了
（业务调用仍 401）—— 那次**真的需要密码重登**（我手动做的那次，P12-BG 现在能自动做）。

## 3. 所以"续期失效"其实是两件事被混成了一件

| | M1 风控墙（**多数**） | M2 会话真死（**少数**） |
|---|---|---|
| 事实 | 首页 418，业务调用被墙挡成 401 | 首页 200，业务调用仍 401 |
| 会话状态 | **没死**（墙解除后同一 cookie 就能用） | 真死了 |
| 正确处置 | 等墙解除（或换出口/换域名），**别重登、别重启** | **密码重登** |
| 旧代码怎么做的 | 判成"refresh_token 失效"→ 写 emergency → 重启 bot 进程 → 每 5 分钟空转，**4~8 小时** | 同样只会重启进程，谁也救不了 |

### P12-BI（今天 14:35）· **先判墙，再谈重登**
升级链前面加一道墙检查 `_home_status()`（首页 418 或"200 + 验证码页"⇒ `wall`）：

```
业务探针 unauth
  ├─ 首页 wall      ⇒ probe="captcha"：不重登、不重启、不写 emergency（等墙解除）
  ├─ 首页探测失败   ⇒ 不下结论，下一轮再判
  └─ 首页 200       ⇒ 会话真死 ⇒ P12-BG 密码重登   ← 这时重登才有意义
```

那支"连续 20 分钟没验证通过就重登"也**先看墙**（墙在的时候浏览器续期请求会被
`418 captcha_required` 挡回来，重登同样过不去，只会白撞风控 + 刷告警）。

`probe="captcha"` 对下游是安全的：巡检与 Socket.IO 都**只认 `"unauth"` 为死**（P12-AR 定的），
所以墙期间不会被误判成"会话死"，也不会把 SIO 的重连退避顶到 1 小时。
