# P12-AM：recap 内容更丰富（屋主："有些单薄"）

> 屋主 2026-09-29："我觉得内容要再丰富完善一些，有些单薄。"

## 1. 为什么必然单薄：格式写死了

`RECAP_PROMPT` 原文：

```
只输出 **3 行**，一行一个主题，不要多也不要少……
💬 大家在聊：<一行，35~55 字>
🎭 群里的事：<一行，25~45 字>
📌 等你回：<一行，20~40 字>
每一行必须……**绝对不要换行**。
```

三行加起来 **80~140 字**，再具体也就那样。而且解析器是 `body[k] = s` —— **每段只保留
最后一行**，就算模型多写也全被丢掉（两个限制叠加，等于把内容锁死在 3 行）。

## 2. 改法（格式 + 解析 + 预算 + 一处沉默截断）

| 位置 | 改动 |
|---|---|
| `prompts/RECAP_PROMPT.md`（与 `brains.RECAP_PROMPT` 同步） | 改成**三段、段内每条一行以「· 」开头（每段 2~3 条，共 6~9 行）**；每段要求写清"谁和谁、聊了什么、结论或分歧"；📌 要"带上他的原话"；并写明**三段都必须写**（实测漏过一段） |
| `runtime/recap.py` | 新增 `_parse_recap_sections()`：**按段累积**（`·`/`-`/`•`/`*` 都认，没有前缀也认）；识别并丢掉"只有标题"的行（`💬 大家在聊：`）；拼装时**由代码补回固定标题与 `· ` 前缀**（不让模型自由发挥） |
| `runtime/recap.py` | **📌 那段不准缺席**：模型漏写时用 `hits`（谁提到过他）补一条 —— 只补代码已知的事实 |
| `brains.generate_recap` | 输出预算 800 → **1200** token |
| `runtime/prompt_tiers.py` | RECAP 的形状描述与 `must_keep` 更新（`· `/三段），`max_newlines` 2 → 14；体检用的 `max_tokens` 400 → 800（否则长输出在体检里被截断、误报"换行数不对"） |

## 3. 顺手抓到的真凶：`lines[:10]`

内容改丰富之后，工具报"段落不全（缺 📌）"。排查发现不是模型漏写，而是收尾那句：

```python
return "\n".join(lines[:10])      # 旧格式总共才 5 行，10 行上限没毛病
```

新格式正常输出就是 **2 + 3×(1 标题 + 3 条) = 14 行** → **最后一段被沉默截掉**。
上限改成 20（头 2 行 + 3 段 × (1 标题 + 5 条)），并加了测试钉住"别再回到 10"。

## 5. 复盘

- **"内容单薄"先查格式约束**：不是模型不行，是提示词把输出锁成了"三行、每行几十字"，
  解析器还只留最后一行。**两个限制叠加**，等于无论喂多好的转录都只能吐出三句。
- **沉默截断最伤人**：`lines[:10]` 在旧格式下完全正确，格式一变就成了 bug，
  而且现场表现是"模型好像漏写了" —— 排查时别先怀疑模型，先看自己有没有切。
- **必填段落要有代码兜底**：📌 那段承载"有没有人找你"这个**用户最在意的信息**，
  不能交给模型的自觉；现在它由 `hits`（代码算出来的事实）保底。
