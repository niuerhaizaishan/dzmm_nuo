# 会话观测补丁

状态：2026-10-06 已部署并开启生产观测。此补丁属于 AUTH-OBS，不是 AUTH-SYNC 或 AUTH-DEC。

## 目的与边界

确认是否发生“浏览器凭据声明的有效期较晚 → 抄回跳过或写回失败 → 文件凭据灌回浏览器 → 认证失败或恢复重启”，并补齐 auto_recover 子进程原先丢弃的恢复决策记录。

不修改原凭据选择、60 秒抄回节流、会话锁等待、页面重载、未授权分类、登录阶梯、重启及告警逻辑；不让 renew 读取观测状态。写回失败时原 _harvest_token 仍按原逻辑返回 True，这个已知问题只通过新记录揭示，留给后续修复。

## 开关与文件

模块默认关闭。生产容器已设置 DZMM_SESSION_OBS=on，auto_recover 继承该环境；生产 compose 模板与服务器均显式设置为 on，避免未来应用模板时丢失开关。off、缺省或其他值关闭观测；本地开发 compose、生产群配置与 .env 均未修改。

| 文件 | 用途 |
|---|---|
| runtime/session_obs.py | 独立观测模块，不参与业务决策 |
| data/page_token_state.json | 最近一次落盘的同步前或同步后快照，原子替换 |
| data/session_events.jsonl | 脱敏事件日志，超过 512 KiB 轮转 |
| data/session_events.jsonl.1 | 仅保留一份旧日志，合计约 1 MiB 上限 |
| data/.session_obs.lock | 独立诊断锁，不使用或占用认证会话锁 |

关闭时不额外读取浏览器 cookie 或写诊断文件。开启后，每次刷新增加同步前、同步后两次本地 cookie 采样，每次设置 0.2 秒等待超时；文件写入没有严格的延迟上限，实际开销仍需上线评估。

正常同类事件每 10 秒最多落盘一次；凭据差异、采样失败、恢复事件优先记录，但所有事件仍受每进程每分钟 120 条硬限制。单条不超过 32 KiB，cookie 摘要最多八项。被限量或跨进程锁忙跳过时尽力携带丢弃计数；观测不保证完整审计。

## 同步取证

观测保留每个候选认证 cookie 的域、路径、目标 origin、24 位 SHA-256 指纹、payload expires_at 与浏览器 cookie expires。两种过期时间分别命名；完整 cookie、access_token、refresh_token、用户 payload 均不进入新文件。

比较按完全相同的 domain/path 配对，不将多域或多路径同名 cookie 混为一份。重复目标不强行选择；无法解析、同有效期但不同凭据、缺少 cookie 均有明确状态。只有目标 origin 匹配的相同范围才标记有效期倒退候选。

抄回结果包括 no_context、throttled、lock_busy、missing_browser_cookie、missing_file_cookie、same、expiry_not_later、write_verified、write_returned_false、write_readback_mismatch、write_verify_error、error。

同步前记录 file_cookie，即本次实际准备灌入的文件快照，以及 browser_context_cookie；同步后重新读取浏览器，记录 browser_context_cookie_after。字段 candidate_expiry_regression=true 表示同步前浏览器有效期较晚、同步后变成了本次文件值。

该标记不能证明凭据被平台撤销，也不证明两份凭据属于同一次登录。expires_at 不是完整版本号；它是进一步排查的候选事件，不作为恢复依据。

正常事件经过采样，快照可能停留在 before 阶段，必须检查 event、at、instance、trace 和各样本 sampled_at，不能把旧快照当成当前会话证明。

## 自动恢复取证

主循环记录 unauthorized 来源是 read 还是 generation，实际恢复拉起、启动失败、重复跳过以及关联的 parent_trace。群 ID 仅以指纹记录。

真正拉起子进程时传递诊断 trace 和父实例标识，保持原子进程命令、stdout/stderr 重定向和去重策略。关闭时 env=None，仍继承原环境。

auto_recover 直接写独立诊断日志，记录等待/取得会话锁、已登录跳过、AppleScript/headless/manual_captcha 的结果、为何请求重启、终止旧 bot 的请求、验证结果及恢复耗时。不开启原始子进程输出，不记录密码或异常正文。

recovery_restart_decision 的 login_mode=already_logged_in 可以识别“未实际重新登录也重启了 bot”；recovery_finished=verified 只表示既有 verify 调用成功，不额外调用业务接口。

记录的重启请求不等同于证明终止成功或新 bot 已就绪，需结合新实例 group_loop_started 和现有 entrypoint 日志。发送侧 task_group_fingerprint 来自当前任务上下文，不声称它一定是后台发送的实际目标群。

## 故障隔离与验证

观测存储、采样、解析异常只影响诊断，新增错误输出只记录异常类型并按一分钟限量。没有自动重试，没有后台采样队列；取消会沿原异步调用传播。文件诊断锁使用非阻塞 flock，Windows 本地采用非阻塞 msvcrt；线程内另有非阻塞锁。

本地测试覆盖节流、锁竞争、写回返回 False、读后不一致、合法新文件同步、域和路径差异、同有效期不同凭据、无 context、JSON/快照写入失败、浏览器错误及超时、跨群 trace 隔离、文件轮转和限量、恢复跳过/成功/失败及异常传播，并验证新诊断不含测试凭据。

验证命令使用既有 pytest 及 vendor 依赖，不安装新依赖，也不运行真实登录、续期、告警或群发送。

本地验证结果：专项回归 112 passed、4 skipped；最终全量 1670 passed、6 skipped。修改文件通过 Python 3.11 语法检查及差异空白检查；实际测试运行环境为本地 Python 3.14，不冒充生产 Python 3.11 运行验证。
