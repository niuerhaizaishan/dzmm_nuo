# 跑团（/跑团）方案设计

> 状态：方案已确认，待实现
> 日期：2026-08-18
> 与方案 A（/剧情）共用状态机框架，区别见"与方案 A 的关系"

## 一、定位

小小糯当 GM（主持人），主持一场**多人角色扮演跑团**。群友 `/加入` 报名、被分配角色、用行动指令扮演，GM 判定推进剧情到结局。

与现有功能的区别：

| 功能 | 群友角色 | 互动方式 |
|------|---------|---------|
| 公演 | 演员（S/M/围观） | 真人文字扮演 |
| 调教 | 发命令者 | 命令真人 |
| 剧情（方案A） | 集体导演 | 投票选走向 |
| **跑团（方案B）** | **演员（扮演角色）** | **自由行动，GM 判定** |

## 二、核心流程

1. **发起**：`/跑团开始 [主题]`（主题可选，不指定 GM 随机）
2. **GM 出剧本**：背景设定 + 角色配置（N 人 M 男 K 女）+ 目标，一次性公布
3. **招募**：GM 提示"这局需要 X 人（Y 男 Z 女）+ 角色身份，想玩的发 `/加入`"；**60 秒截止，凑不齐自动取消**
4. **分配角色**：GM 按性别把加入者分到角色上，@ 每个人公布身份
5. **游戏循环**：GM 给场景 → 加入者 `/做 xxx` 或 `/xxx` 行动 → GM 综合判定、推进
6. **结局 + 结算**

## 三、剧情怎么确定

分两层，发起者只碰第一层，第二层 GM 全包：

1. **主题/方向**（发起者可选）：`/跑团开始 校园恐怖` → 指定主题；`/跑团开始` → GM 随机挑
2. **剧本**（GM 生成）：GM 根据主题生成完整剧本：
   - **背景设定**（地点、氛围、悬念）
   - **角色配置**（这局需要几个角色、几男几女、每个角色身份）——就是招募时 GM 提示的"几男几女"，招募和剧本咬合
   - **目标**（这局要达成什么，如"逃出深夜的教学楼"）

**角色结构**：GM 生成剧本时随机决定——可有核心主角，也可群像，不额外约束。

举例：`/跑团开始 校园恐怖` → GM 生成"深夜女生宿舍"背景，需要 **3 人（2 女 1 男）**：女主、女主闺蜜（女）、混进来的学长（男），目标是"找出半夜敲门的人是谁"。

## 四、招募

- 60 秒窗口，`/加入` 报名，GM 读 profiles.json 的 gender 确定性别
- 招募前 GM 先提示"需要 X 人（Y 男 Z 女）+ 角色身份"
- 60 秒凑不齐 → 自动取消（GM 提示"人没齐，本局取消啦"）
- 至少 2 人才开（1 人和发骚没区别）

## 五、行动识别

- 只认"已加入玩家"的发言，且**必须带 `/`**
- `/做 xxx` 和 `/xxx` 都算行动（加不加"做"都行）
- 非加入者 / 裸发言 → GM 忽略或提示"要先 /加入 哦"

## 六、GM 全程提示

招募 / 分角 / 行动引导 / 判定推进 / 结局，每个环节 GM 都出声主持。

## 七、结局与结算

| 角色 | 加成 |
|------|------|
| 发起人 | +15 |
| 其他加入者 | +10 |
| MVP（GM 结局时主观评，行动最投入/最有梗/最贴角色） | 额外 +5 |

## 八、状态机（`state.json` 每群 `trpg` 字段）

```json
{
  "active": true,
  "phase": "招募",            // 招募 / 行动 / 生成中
  "theme": "校园恐怖",
  "background": "深夜的女生宿舍…",
  "goal": "找出半夜敲门的人是谁",
  "roles": [
    {"name": "女主", "gender": "女"},
    {"name": "闺蜜", "gender": "女"},
    {"name": "学长", "gender": "男"}
  ],
  "players": {"<uid>": "女主"},
  "recruit_deadline": 1730000000,
  "round": 1,
  "max_round": 6,
  "history": ["第1轮场景+行动…", "第2轮…"]
}
```

## 九、GM 生成（brains.py 三个 prompt）

- `TRPG_SETUP_PROMPT`：主题 → 背景 + 角色配置 + 目标
- `TRPG_STEP_PROMPT`：历史 + 本轮玩家行动 → 判定 + 下一段场景
- `TRPG_END_PROMPT`：完整历史 → 结局 + MVP 提名

文风沿用既定口味：色色、直白露骨、加羞辱。剧情围绕加入者扮演的角色展开。

## 十、指令清单

| 指令 | 作用 |
|------|------|
| `/跑团开始 [主题]` | 发起 |
| `/加入` | 报名参与 |
| `/做 xxx` / `/xxx` | 行动（加不加"做"都行） |
| `/跑团结束` | 提前结束 → 直接进结局 |
| `/停止 /停下 /结束` | 停止词（只认带斜杠） |

## 十一、屏蔽（跑团进行中）

- 指令：只放行 `/加入`（招募期）、`/做`/`/xxx`（游戏期）、`/跑团结束`、停止词；其余全屏蔽
- 自动触发：屏蔽排行（12/18 点）、高潮事件、新成员欢迎、公演/调教/剧情互动等一切主动发消息的触发

## 十二、技术边界与隐患

- 换行 ≤10 行、单条约 333 字（生成端控制）
- 剧情连贯性：`history` 每轮传入 prompt
- 招募超时取消：`recruit_deadline` + 主循环检查
- 和公演/调教/剧情互斥：跑团中发其他模式指令 → 提示先 `/跑团结束`
