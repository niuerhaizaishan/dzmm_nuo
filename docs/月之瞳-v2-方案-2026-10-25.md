### 2.1 关键事实

| 群消息走官方 Bot API webhook | 入群后消息是**推送**而非轮询，延迟 1~2 秒 |

### 2.2 路线对比（更新）

| 方案 | 做法 | 全自动 | 改动 | 工作量 |
| --- | --- | --- | --- | --- |
| 旧 A | DM 输出震动行，人工发 `/震` | ✗ | 只改提示词 | 半天 |
| 旧 B | 机器人旁听团本 | 当时判断不可行 → **现在可行** | 入群 + 解析 | 1 天 |
| 旧 C | 把规则搬进程序、机器人当 DM | ✓ | 最大 | 2 天+ |
| **新 D（推荐）** | **小小糯入群旁听 DM，解析结构化行 → 直接触发触觉** | **✓** | 提示词 + 一个解析器 | **1 天** |
| 新 E（备选） | 拉不进群时，用你的账号跑守护进程读群 | ✓ | 需要你的登录态 | 1.5 天 |

**推荐 D**：不动玩法、不让机器人抢 DM 的话，也就不用重写规则；触觉与结算的一致性靠「DM 输出的结构化行」保证。

### 2.3 D 方案的工作方式

```
Dungeon Master（平台 AI）每回合输出叙述 + 一行【震动】
        ↓ 群消息推送（webhook）
小小糯（静默旁听，不发言）
        ↓ 解析【震动】行 → 冷却/上限/开关
触觉调度器 → ShareClient → 房主页面 → 蓝牙 → Lush 4 Mini
```

要点：

1. **入群**：你在群里把小小糯拉进来（或在成员列表邀请）。它只旁听，不回复任何消息。
2. **静默**：给该群配置 `mute`/只读，确保它不会插嘴剧情（现有 config 支持按群静音）。
3. **结构化行**：DM 提示词加一段（见 2.4），保证每回合最多一行、格式固定。**这是全自动可靠性的关键**——不去猜几百字的散文。
4. **解析器**：只听 `sent_by == 3adb1285`（DM）的消息；正则抓 `【震动】目标 强度 时长`；抓不到就**不触发**（宁可不震，也不瞎震）。
5. **触发**：走 `ShareClient`（房主页面渠道），不经过群指令、不需要谁手动发 `/震`。
6. **安全**：房主页面「允许小小糯控制」是总开关；群里任何人说「关掉震动」→ 停并暂停本回合；`/停` 优先；每回合最多 2 次、同类 10 秒冷却。

### 2.3.1 小小糯的角色边界（按你的要求）

**它只做一件事：读。** 具体说：

| 做 | 不做 |
| --- | --- |
| 读取群里的消息（含 DM 的叙述） | **不发言**（连"已震动"这种回执也不发） |
| 解析 DM 输出里的 `【震动】` 行 | 不掷骰、不判格、不管密码、不推进剧情 |
| 触发触觉（房主页面渠道） | 不参与任何规则判定，也不替 DM 记忆 |

也就是说：加入群只为了**拿到消息**（DZMM 的群消息靠成员身份 + 官方 webhook 推送，不在群里就收不到），
成员列表里多一个"小小糯"，但整局游戏里它**一言不发**，玩家感知不到它。

如果连"多一个成员"你都不想要，备选是 **E 方案**：用你的账号跑一个守护进程轮询读取
（不在群里新增成员，但要长期保持你的登录态，且消息延迟比 webhook 高）。这个由你选。

### 2.4 DM 提示词补丁（新增一段，约 6 行）

```
# 触觉输出（每回合最多一行，放在状态栏之前，单独成行）
当本回合发生下列事件时输出一行，格式严格照写，不解释、不写进正文：
【震动】<受事角色名> <强度%> <时长ms>
  普通装置触发 → 25% 600     ★装置／雾浓 → 45% 900
  滑倒 → 20% 300            拆解/挣脱成功 → 20% 400
  对抗失败被挂装置 → 55% 1200   集齐一位密码 → 70% 900
  拿到宝石 → 80% 1500        失守 → 100% 3000
没有触觉事件的回合，不要输出这一行。
```

### 2.5 事件 → 触觉映射（默认，可调）

| 事件 | 强度 | 时长 | 形态 |
| --- | --- | --- | --- |
| 普通装置（+1） | 25% | 600 | 单发 |
| ★装置 / 修复室雾浓 | 45% | 900 | 单发 |
| 掷 1 滑倒 | 20% | 300 | 两连击（间隔 300ms） |
| 拆解 / 挣脱成功 | 20% | 400 | 两连轻击 |
| 对抗失败被挂装置 | 55% | 1200 | 单发 |
| 集齐一位密码 | 70% | 900 | + 90% / 500 两段 |
| 拿到宝石 | 80% | 1500 | 单发 |
| 失守 | 100% | 3000 | 长震后必停 |
| 逃出 / 两圈结束 | 0 | — | 直接停 |

规则：每回合最多 2 次；同类 10 秒冷却；默认上限 70%（仅失守允许 100%）。

### 2.6 安全与边界

1. 只对**房主角色**（糯糯～）触发——设备只有一台
2. 「允许小小糯控制」是总开关；关闭即整局无触觉
3. 群里任何人说「关掉震动 / 暂停」→ 立即停并跳过本回合
4. 触觉只来自 DM 的结构化行（=已确认结算），**回顾、重写、刷新都不会重放**
5. DM 输出格式异常 → 不触发，并记一条日志（便于回头调提示词）
6. 设备断线 → 只影响触觉，游戏照常
7. 不做：露骨情节或性反应数值 → 刺激强度的映射；这条我不设计

### 2.7 密码方案（每处一位、每局随机）

你的想法更干净：**每处只藏一位 0~9**，三处拼成三位数（例：格5=`7`、格9=`2`、格12=`9` → `729`），保险柜要输入 `729`。

难点不在「随机」，在**谁来随机、谁记得住**——DM 是 AI，忘掉或改数是最常见的翻车方式。三个方案：

| 方案 | 谁生成 | 怎么防漂移 | 风险 | 推荐度 |
| --- | --- | --- | --- | --- |
| **P1 DM 掷骰** | DM 开局掷 3 次 d10，记在"心里" | 要求在每次状态栏用 `①②③` 显示"已揭晓几位"，未揭晓的不显示 | LLM 可能中途改数或忘掉 → 开柜判定前后不一致 | 中 |
| **P2 候选组 + 掷 1d4** | DM 开局掷 1d4，从提示词里的 4 组候选里选一组 | 只需记住"第几组"一个数字，比记三个数稳 | 仍可能记错组；但错也只错在"整组"层面，容易在日志里发现 | 中高 |
| ~~P3 小小糯生成 + 校验~~ | ~~小小糯生成并判定~~ | — | **已否决**：你要求小小糯不参与团本过程，不能由它判定密码 | — |

**结论：走 P2**（既然小小糯不参与判定，密码必须由 DM 自己管，而 P2 是它最不容易翻车的形式）。

P2 的实施细节（写进提示词）：
- 提示词里预置 **4 组**候选（**已定，就用这四组**）：A=`7-2-9`、B=`4-8-1`、C=`9-3-6`、D=`2-7-5`
- 开局时 DM 掷 **1d4** 选定一组，只在内部记录「本局用 C 组」，**不公布**
- 玩家拆掉某处装置时，DM 报出该处对应的那**一位**数字
- 玩家在群里说「密码 936」→ DM 比对"本局组"并判定是否开柜
- 为降低漂移：状态栏固定加一格 `【密码】①— ②— ③—`，只显示已揭晓的数；DM 每回合照着它抄，比自己"记在心里"稳得多
- 如果 DM 中途说漏/改数：以状态栏已公布的数字为准（规则写死），避免前后打架

**为什么不选 P1**：3 次 d10 要让 AI 记住三个数，比记住"用第几组"更容易漂移；4 组候选 × 1d4 已经足够随机（每局 1/4 变化），也够用。

## 五、新群接入：要不要重新部署？

**不用。** 不重建镜像、不改 compose、不动 Caddy。三件事：

1. **你**：把小小糯拉进新群（平台侧，一次操作）
2. **我**：把新群 cid 加进 `/opt/dzmm/config/config.json` 的 groups，只读模式：
   ```json
   {"cid": "<新群cid>", "alias": "月之瞳", "enabled": true,
    "mute": true, "persona": "", "features": {}}
   ```
   - `mute: true` 在代码里的语义就是**「静默监控：只读不回」**（`config_store.py` 注释原文）
   - `features: {}` 表示不接任何自动发言/开关
   - 如果还想在团本群里手动发 `/震`，再加 `"slash_cmds": true`
3. **我**：`docker compose restart dzmm-bot`（约 15 秒，重启后自动重新 join 所有群）

为什么必须重启：**群清单不热更新**。Socket.IO 订阅器在启动时按群列表建长连接，运行中改群清单会出现「面板里加了群、其实收不到消息」的假象（`runtime/hotload.py` 里专门写了这条）。热更新只覆盖功能开关、参数、按群集合、人设和提示词。

**不用重配 webhook**：回调地址是跟着机器人账号走的，机器人成为新群成员后，平台就会把该群的群消息推过来。

需要的信息只有一个：**新群的 cid**（群链接里 `?c=` 后面那串）。

## 七、提示词要极简（你的要求）

现状：DM 提示词 **约 4,600 字 / 10 小节**，其中「落格结算」1,251 字、「状态栏与输出格式」1,046 字。
字数越多，模型越容易漏规则；它每回合都要照着执行，越长越容易走样。

**目标：压到 ≤1,600 字（约原来的 1/3），6 块，只留规则。**

### 骨架

| 块 | 写什么 | 篇幅 |
| --- | --- | --- |
| 1 身份 | 你是主持人/裁判；不扮演玩家；骰子玩家掷你只核对；输了照写 | ~80 字 |
| 2 回合 | 两人各报一个行动 → 掷 1d6 前进 → 落格结算 → 一条消息（正文＋四种行＋状态栏） | ~120 字 |
| 3 掷骰 | 1d6；掷 6 连掷最多 3 次；掷 1 走 1 格并滑倒 +1；连掷遇 1 中断；过起点只算一次 | ~120 字 |
| 4 落格 | **表格化**，一行一类：装置／任务／机会／保险柜／宝石／出口／同格 | ~300 字 |
| 5 状态栏 | 三行模板原样给出 ＋「阈值＝10−掉格」「着装用固定状态词」「漏行算违规」 | ~250 字 |
| 6 红线 | 尺度跟随玩家；不排泄/不血腥；说停就停；装置给解除窗口 | ~120 字 |
| 触觉 | `【震动】角色 强度% 时长ms` 的触发与格式 | ~60 字 |

### 删掉什么（这是"极简"的关键）

- **四种行的重复示例**：每种现在给 2~3 个例子，删到 1 个
- **六项自查清单**：压成一句「每回合检查：位置、发情、着装、阈值、密码、手牌」
- **文风大段描述**：留一句「第三人称、只写外在、身体细节随发情与着装推进」
- **重复强调**：「不许代劳／不许替他掷」现在出现 3 处，留 1 处
- **可推导内容**：「★=+2、修复室+1」重复 3 次，只在落格表写一次
- **数据表**（47 台装置、12 条题、结局处置段）：~~留在角色卡 A，不进提示词~~ →
  **2026-10-25 晚改：移进提示词**（角色卡只留指针）。原因：平台是否真把「仅 AI DM 可见」
  那段喂给 DM 不确定，而"格 13 第 3 台是什么"必须精确；放卡里模型容易当性格描写读。

### 不删的

- 判定与结算的具体数值（这块含糊就会算错）
- 状态栏模板（每回合的执行锚点）
- 红线三条
- 触觉那一行（解析器靠它）

### 顺带的好处

提示词短了，**解析器也更稳**：`【震动】` 行埋在 4,600 字里和埋在 1,500 字里，模型漏写的概率完全不同。
