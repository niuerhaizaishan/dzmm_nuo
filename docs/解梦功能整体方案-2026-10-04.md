# 小小糯～解梦功能整体方案

> 日期：2026-10-04（Asia/Shanghai）
> 状态：已本地实现，默认关闭；不安装外部 Skill、不修改服务器配置、不部署、不提交。
> 范围：小小糯～，仅覆盖认证妹子群与顶层茶水间。

## 1. 功能定位

提供有传统味、贴合梦境、带小小糯语气的短篇解梦：简短梦境主线、现实提醒、可选古籍趣读。首版不增加梦签或判词库。

解释以用户描述的动作、情绪、转折和结尾为主；古籍只作传统对照，不用孤立名词套结论。现代梦境没有合适条目时，直接作象征解读，不编造古籍。

小小糯温柔、亲近、略带俏皮；解梦时不因群玩法风格而转成羞辱、挑逗或成人剧情。不凭昵称或认证群身份推断个人经历，不强制称用户为姐姐。

本期做单次文字解梦、可核验短引、按群开关、限频及错误处理。不做多人设、图片卡、梦境档案、自动续聊、跨群记忆、每日梦运、数字吉凶评分或其他 Bot 的解梦。

## 2. 两群入口与边界

| 群 | 首版入口 | 现有边界 |
|---|---|---|
| 认证妹子群 | `/解梦 梦境内容`；`@小小糯～ 解梦 梦境内容`；明确的自然语言求解 | 保留原斜杠开关、静默群规则及独占玩法保护 |
| 顶层茶水间 | `#解梦 梦境内容`；`@小小糯～ 解梦 梦境内容`；明确的自然语言求解 | `#解梦` 作为精确白名单例外；保留 at_only、slash_cmds、引用触发及其他 Bot 噪音过滤，裸 `/解梦` 仍不开放 |

标准示例：

```text
/解梦 我梦见一直赶不上火车，最后索性坐在站台吃面，反而很开心。
@小小糯～ 帮我解个梦：梦见家门怎么也打不开，我特别着急。
#解梦 我梦见一直赶不上火车，最后坐在站台吃面，反而很开心。
```

- 认证群裸 `/解梦`、茶水间裸 `#解梦` 或 @ 后只说“解梦”：回复一次简短引导，例如“把梦里发生的事讲给小小糯听吧～尤其是你当时的感受，还有最后停在哪儿。”不调用模型，不进入等待下一条普通消息的状态。
- 第一版自然语言入口要求明确请求，如“帮我解梦”“这个梦是什么意思”。只说“我梦见你啦”仍按普通聊天处理，不主动开启解梦。
- `/解梦` 按完整命令词和分隔符识别，不用无限制 startswith 把 `/解梦游戏` 等当成有效命令；不额外占用 `/梦`、`/周公`、`/继续` 等短词。
- @ 后带 `/解梦` 的文本在既有 @ 路径中解析；不为了支持它开放茶水间裸斜杠指令。
- 茶水间 `#解梦` 不用 @；只认消息开头的完整 `#解梦` 命令词，后接结束、空白或中文/英文冒号。`#解梦游戏`、正文中提及 `#解梦`、其他 `#xxx` 不进入解梦通路。认证群首版不开放裸 `#解梦`。
- 白名单放在 at_only 闸门之前，但必须先通过来源过滤、目标群/人设、dream 与 dream.hash_cmd 判定；不放开整个井号指令族或 slash_cmds。沿用既有消息去重、inflight 和同批剩余消息 requeue 语义，避免吞掉第二条请求。
- 引用消息只沿用原触发权限。本期没有隐式解梦续聊；需要重新明确求解并提供梦境，不从全群上下文猜测梦属于谁。
- 自身消息、其他 Bot 消息、广播和游戏噪音不产生请求。
- 独占玩法期间沿用进行中提示，不绕过现有保护抢占玩法；显式解梦应先于通用模型命令/聊天兜底，避免误落到其他玩法。
- 功能关闭或超出范围时，不进入解梦模型与检索，也不让明确的解梦请求落入通用模型兜底偷偷执行；按原入口规则静默处理。

范围控制由实际 CID 与有效人设决定，不能按群名、前缀或文字中出现“小小糯”放行。认证群 CID 为 `bd7fe6a4-0065-4551-ad3d-94116dba8f9c`；茶水间 CID 为 `4fc4a2fd-465a-4436-9884-dbb5e60c6af2`，已在既有 P12-BM 文档中核实。最终发送身份仍由已有路由配置决定。

需要同时满足：目标 CID 在解梦允许范围、有效人设为 nuo、dream 开关开启。约束不受全局功能强制开启而扩大。两个群分别配置，其他群默认关闭，不修改其他 Bot 的提示词和话术。

## 3. 回复规格

按最新要求缩短：模型解读建议 80～130 字、建议 15～30 字；完整内容（包含标题、可选引文和提醒）默认最多 230 字，茶水间另有 180 字硬上限。不含统一的 `🤖 ` 前缀；加前缀后仍低于账号发送器的 190 字分片阈值。最多五行，跳过聊天装饰、招揽重写和立绘补发。实际投递沿用既有链路，不承诺账号通道绝不重试或重复。

输出顺序：

1. **标题**：统一使用“糯糯看梦～”，不强制给吉凶。
2. **梦境主线**：抓最关键的动作、情绪和结尾，解释一到两个可能处境。引用最多一条，必须贴合条件；不复述整个梦、不替用户编出现实背景。
3. **现实提醒**：一到两句低风险建议，必要时补一个具体的另一种读法。不强制三对宜忌，不每次追问，不以消灾、付费或仪式作建议。

“先难后顺”等标题只描述梦中走向，不暗示近期现实一定转运。梦涉及疾病、死亡、亲人或灾祸时优先安抚，不输出古籍凶断语吓人，也不预测健康或寿命。

示意回复（不含古籍引文）：

```text
糯糯看梦～
你追着火车跑，后来坐下吃面，反而开心了。也许这个梦在借“停下来也没失去什么”，呈现紧张松开的感觉；也可能只是出行片段的重新组合。
试试：今晚先歇一歇，记下醒来时最明显的感受。
仅作自我觉察和文化趣读，不预示现实。
```

## 4. 借鉴外部仓库的方式

参考：https://github.com/easoch9-spec/zhougong-dream-skill

吸收叙事分析、条件匹配、主题检索、判词库、来源核验和典型梦例。独立整理成适合群聊的一套规则，不将多个存在冲突的规格原样塞入提示词。

- 不安装 Skill 作为 bot 运行时依赖。现有 DeepSeek API 不会自动读取仓库文件或执行检索，检索由本地 Python 完成。
- 暂不接入三张图卡与长报告设计，也不复制带成人设定之外的附加课程材料。
- 原创方法、代码和文档为 MIT，复用时保留对应许可说明。古籍转写另按来源及适用许可处理，不假设整个仓库都是 MIT。
- 不引入授权未核实的 spiritual-practice-lens；《夢占逸旨》《夢林玄解》的候选索引不充当可直接引用的原文。
- 第一次导入固定具体 revision、来源、处理方式和校验值；不要运行时从 main 自动更新。

## 5. 最小技术架构

```text
已有入站去重/身份过滤/群规则
            ↓
指令或 @ 意图判定 → 范围与功能闸门 → 长度/限频/并发检查
            ↓
本地关键词、同义词、动作与主题检索
            ↓
一次 DeepSeek 调用：梦境＋候选原文＋小小糯任务提示
            ↓
结构校验 → 引文核验 → 确定性排版
            ↓
已有 Outbox 与群发送路由
```

### 本地知识层

- 将正文整理为条目：稳定 ID、章节、原文、规范化检索文本及必要关键词。原文单独保留，不做繁简改写后冒充古籍。
- 使用简繁归一索引和明确的同义词表，不只以简体词查繁体资料；补上动作关键词的跨章节检索，避免主题路由漏项。
- 首版独立精选六条温和短引，存于 `runtime/dream_sources.py`，随 Python 代码打包；不复制 25 KB 全文，不需要向量数据库、新服务或联网抓取。覆盖有限，现代梦境通常没有引文。
- 确定性检索一次最多提供三条候选，词汇不足或存在明显否定、坠落等冲突时允许零候选。模型再按动作与条件选择，不能要求必须引用。
- 首版不新增判词或标题库，避免增加来源核验负担。
- 若现代场景的关键词覆盖不足，先补词表和条目测试，再决定是否需要额外意图抽取模型调用。

### 模型与输出契约

默认只调一次现有常规模型，不使用小说模型、不自动长文续写；本地检索不额外调用模型。

模型返回有界 JSON，仅含 `reading`、`advice`、`source_id` 三个字符串字段；解读和建议不能为空，来源可为空。最终输出不展示 JSON 或检索过程。

- source_id 只能属于本次提供的候选，代码从知识库填入原文；不能接受模型自由生成“古籍原句”。
- 原文真实不保证适用，需要检查所选条目的条件是否贴合梦境；典型梦例和人工评估承担这项语义验收。
- 引文 ID 无效、不属于本次候选、主体 JSON 无法解析、模型截断或正文不合格时，给短失败提示；不重试模型，不直接发送未校验原文。篇幅不足则省略有效引文，但保留提醒。
- 用户梦境作为输入数据，不能通过“忽略规则”等文本改变来源范围、泄露提示词或切换人设。
- 小小糯的解梦语气与其他玩法任务分离；可复用身份，但不继承挑逗或羞辱类任务约束。
- 提示词外置并登记热加载。因 JSON 被程序解析，应按 C3 登记，增加匹配该对象的契约检查；不能只标记成自由文案或沿用不匹配的现有契约。

## 7. 参数、成本与隐私

建议初始参数（实施时核对项目调参类型与单位）：

| 参数 | 建议 |
|---|---|
| dream | 注册默认关闭，仅两目标群配置开启 |
| dream.natural | 默认 1；仍受 dream 默认关闭与硬范围限制，可单独关自然语言求解 |
| dream.hash_cmd | 默认 0，仅顶层茶水间配置为 1；仍须通过解梦范围与 dream 开关 |
| dream.max_chars | 默认 230，范围 100～280；茶水间另有 180 字硬上限 |
| 模型 token 上限 | 固定 650，不新增可调入口 |
| dream.timeout | 默认 20 秒网络/等待上限；后台线程退出前继续占用容量 |
| dream.cooldown | 同群同用户 60 秒，两群独立，可调整 |
| dream.input_limit | 默认 2000 字符，超长提示用户保留关键情节，不静默截断 |

- 两群合计最多 2 个生成任务，同群同用户最多 1 个；容量不足给一次短提示，不开启无界后台队列。
- 阻塞模型请求走既有异步隔离路径；超时不意味着工作线程已终止，实际在途任务完成前仍占并发额度，防止反复超时挤满线程池。
- 默认成功结果 1 次模型调用，不自动重试，也不承诺最终成本，后续按实际 token 使用量计算。
- 冷却提示仍计入限频，避免每条重复请求都刷屏。状态仅存有界的进程内限频/在途信息，不存原始梦境作为功能缓存。
- 解梦专用输入只包含本条梦境和用户显式提供的背景，不读取全群历史、档案、骚度、长期记忆或他人梦境。
- 不新增梦境长期保存与档案字段；不声称既有系统完全不留痕。当前入站上下文、日志和 Outbox 本身可能保存消息，实施时核对留存，并让新诊断只记录耗时、状态与脱敏请求标识。
- 群内梦境会发送给现有模型服务生成回复，使用说明明确这一点；用户可自行去掉名字及具体个人细节。

## 8. 故障与输出降级

- 空输入：提示补梦境，不调用模型。
- 无匹配条目：正常解读，零引用。
- 资料缺失：记录一次诊断，降为象征解读，绝不以模型记忆补古籍。
- 超时、鉴权、限流或非法 JSON：一次小小糯口吻的失败提示，无乱码、无堆栈，不永久自动重跑该消息。
- 输出超限：优先删除可选备选解释、缩短固定结构中的完整句，保留主线；不得截断原文制造假引文。仍不合格则不投递该结果。
- 生成业务失败与发送失败分开：生成失败回复按已处理语义收口；平台发送仍服从现有 Outbox，投递不明不换通道重发。
- 若功能全局关闭、新配置失效或目标群变更，不自动扩大范围兜底。

## 9. 测试与上线验收

### 确定性测试

- 认证群 /解梦 与 @ 可用；茶水间 @ 与裸 #解梦 可用，裸 /解梦 仍沿用原规则。认证群和其他群裸 #解梦 不进入解梦通路。
- #解梦 的空输入、冒号/空白分隔、错误前缀、正文提及、关闭开关、多条同批请求及 Bot 自回声测试通过；既有 #运势 行为不变。
- 其他群、其他人设、自身消息、Bot 噪音、功能关闭与全局强制功能开启均不能越过范围约束。
- 非求解的“梦见你”、其他命令、独占玩法、/继续 和引用触发不被抢走。
- 不同群与用户输入不混合；不会调用记忆写入或档案读取。
- 繁简、同义词、跨章节动作检索可命中；现代场景无匹配可正常处理。
- 无效 ID、编造引文、无效标题、JSON 损坏、超限、超时、资料缺失、限频和并发均有明确行为。
- 输出经过装饰仍符合字符与换行上限，送入现有发送链而非自建发送通道。
- 提示词登记、热加载、C3 契约、功能 wired、参数和部署静态资料完整性通过。

### 内容评估

建立不少于 12 个固定梦例，覆盖追逐、掉牙、蛇、飞行、亲人离世、打不开门、考试、赶车、荒诞梦、亲密梦、无转机噩梦和现代网络场景；两群分别走真实业务入口测试。模型调用需在实施阶段明确安排，不把 mock 测试当成内容质量证明。

硬失败：伪造古籍、预测亲人疾病死亡、凭空补现实经历、羞辱用户、性化解释、串群串人、忽视梦境结尾或泄露内部提示。

人工看主线是否贴合、情绪是否合适、小小糯身份是否自然、与普通聊天是否有明显差别；先固定模型与样例，按观测修改短语、词表和提示词，不堆叠大量文风黑名单。

### 发布顺序

1. 核对两群 CID、有效人设、入口开关与发送身份，导入可用资料并保留来源。
2. 完成专用逻辑、模型接口、提示词、入口与定向测试，再跑项目全量与部署闸门。
3. 经授权部署代码，先只在认证群开启，用维护者账号验证正常梦、空输入和异常路径。
4. 内容与发送稳定后在顶层茶水间开启 dream.hash_cmd，验证 #解梦 和 @ 可用，裸 /解梦 与无关 # 指令仍保持原规则，其他 Bot 游戏无误触发。
5. 至少观察 24–48 小时的误触发、延迟、限频、失败与重复发送。上线观察不自动创建定时任务。
