## 一、运势：两天一个分数

### 现象（线上原文，注意 `sent_at` 是 **UTC**，CST = +8h）

```
御褚  09-29 07:37 CST → 51 分 ；  09-30 07:12 CST → 51 分      ← 跨天却同分 ✅ 屋主没看错
囡囡  09-29 18:32 CST → 77 分 ；  09-30 08:28 CST → 86 分      ← 跨了"五行块"所以变了
糯糯  09-29 00:00 CST → 95 分 ；  09-29 18:32 CST → 95 分      ← 同一天，本来就该同分
```

### 根因

算分（`runtime/fortune.py::_fortune_calc`）=

```
命基(按本命五行，固定) + 名格 + 本命 + 人和 + 日冲/合
```

其中"名格 / 本命"看的是**当日天干的五行** —— 而天干五行**两天才换一次**
（甲乙木、丙丁火、戊己土、庚辛金、壬癸水）：

```
09-27 甲辰(木)  09-28 乙巳(木)  09-29 丙午(火)  09-30 丁未(火)  10-01 戊申(土)…
```

⇒ 同一"五行块"内的两天，分数**完全相同**（御褚那两天都是"火"）。

**四维（财运/事业/感情/健康）更糟**：它的 seed 原来只按**名字**算
（`sum(ord(c) for c in name) % 7`）⇒ 同一个人**永远**是那四个数。

### rose 群有没有这个问题：**没有**

玫瑰房走的是另一套（`runtime/sign.py:274`）：

```python
h = hashlib.md5((uid + "|" + date_str + "|" + sign).encode("utf-8")).hexdigest()
```

**日期进了哈希** ⇒ 每天必然变。认证群这套该照它改。

### 修法（照玫瑰房的思路，但保留"命理可解释"）

| # | 改动 | 说明 |
|---|---|---|
| 1 | 新增**日干阴阳**项：甲丙戊庚壬＝阳 **+3**、乙丁己辛癸＝阴 **−3** | 阴阳是**隔天交替**的 ⇒ 分数**必然天天变**；量级取 ±3（"同五行、阴阳不同力道略差"） |
| 2 | 四维 seed **补上日期**（`dt_now.toordinal()`） | 四维不再永远不变 |
| 3 | 卡面展示：算式行加 `± 阴阳3`，命盘行标 `（阳）/（阴）` | 不然"分数变了"看着像玄学 |

**同一天同一人仍然**完全稳定**（不引入随机）**，历史分数不受影响。

### 验收


## 二、发骚正文太长（"一半就行"）

### 现象

`/发骚` 走的是 `runtime/fasao.py::scene()`（涩涩骰子），线上实测正文：

```
09-30 00:56  🎲 紫苑 × 更衣室 × 失禁play × 戴项圈    len=1325
09-30 00:57  🎲 糯糯～（…） × 更衣室 × 口爆 × …      len=2201
```

### 根因

`prompts/SCENE_PROMPT.md` 把长度**写死**了：

```
- 700-1100字…
- 【长度】写到 700 字以上再收尾；该分段就分段（一般 12-20 行）…
```

外加 `brains.SCENE_MAX_TOKENS = 1800`（2026-09-27 屋主曾报"有截断/内容太少"而调高的）。

### 为什么不能直接改提示词默认档

**上班群 09-27 提过"发骚的内容太少了吧"**（见 `docs/P12-W-四项输出优化.md`），
一刀切改小会把那个需求推翻。

### 修法：长度改成**按群注入**

| # | 改动 | 说明 |
|---|---|---|
| 1 | 提示词（`prompts/SCENE_PROMPT.md` ＋ `brains.SCENE_PROMPT`，逐字节一致） | 长度改为"**以输入里的【长度要求】为准**，没给就用默认档 700-1100 字 / 12-20 行" |
| 2 | 新参数 **`scene.length`**（字符串，默认空；`runtime/features.py`） | 空 = 不注入，行为一个字不变 |
| 3 | `runtime/fasao.py::scene()` | 配了就往 `ai_input` 追加 `【长度要求】…（写够就收尾，不要为了凑长度继续往下写）` |
| 4 | 认证群 tuning | `scene.max_tokens = 900`（原 1800）、`scene.length = "350-550 字，最多 8 行"` |
| 5 | 上班群 | **不配** ⇒ 仍是 1800 + 700-1100 字，完全没动 |

### 验收（离线真生成，未发送、未改任何人状态）

```
认证群 scene.max_tokens = 900 | scene.length = '350-550 字，最多 8 行'
--- 第 1 次：480 字 / 7 行  用时 2.7s
--- 第 2 次：514 字 / 9 行  用时 2.7s
```

**1325 / 2201 字 → 480 / 514 字**，正好"一半" ✅。

测试：`tests/test_long_output.py::test_scene_length_hint_is_injected_per_group`
（配了才注入、没配一个字不加），并更新了原来断言"字以上再收尾"的旧用例；
`tests/test_tuning.py` 的默认值对照表加 `("scene.length", "")`。

## 三、复盘

- **"粒度"问题要靠"跨天同人"的样本才看得出来**：单看一张卡完全正常（有分数、有宜忌），
  只有把同一个人的**连续两天**摆在一起才发现一模一样。而且平台的 `sent_at` 是 **UTC**，
  我第一遍按 UTC 读还把"同一天两张卡"看成了"跨天同分"——**日期先归一到 CST 再比**。
- **对照功能是最快的诊断**：屋主问"rose 群有没有这个问题"，答案直接在
  `runtime/sign.py` 里（它把日期放进 md5）——**同一类需求的两套实现，往往一套对一套错**。
- **"改短"要先问"谁要长"**：发骚长度在两个群的口径相反（认证群太长的抱怨 vs
  上班群太短的抱怨），所以只能做成**按群参数**，不能改共享提示词的默认档。
- **提示词里的硬数字是隐藏的单点**：`700-1100字` 写死在共享提示词里 ⇒ 任何按群差异都做不了。
  改成"以运行时给的要求为准"之后，同一份提示词才真正可复用。
