# P12-AN：账号通道单条上限 200 字（长回复静默失败）

> 屋主 2026-09-29："**茶水间@你怎么没反应了？**"

## 1. 现象与初判

茶水间（`4fc4a2fd`，779 人，**没有 Bot，只走账号通道**）里 @ 她，日志显示：

```
11:27:00 👋 [4fc4a2fd] @消息: @小小糯～ 今天上午发生了什么？
11:27:03 📮 [4fc4a2fd] 回顾: 糯糯 窗口 今天上午 … 共 529 条
11:27:03 💬 🤖 📮 你不在的时候（…）        ← 回复生成成功
11:27:09   ⚠️ 假成功检测：消息未投递到群里，重试
11:27:14   ⚠️ 假成功检测：消息未投递到群里，重试
11:27:16   fallback(DZMMSocket): ✅ cid=4fc4a2fd
```

而**群里一条都没有**（读最近 100 条，我们账号只发出去 1 条 —— 那条是 11:07 的**短**回顾，
窗口只有 10 分钟）。出站队列里它们却全是 `status=sent`。

## 2. 夹逼出真正的限制：**200 字**

在**自检群**（`bot测试`）里真发真读回，逐个试：

| 消息长度 | 结果 |
|---|---|
| 8 / 12 / 20 / 108 / **190** 字 | ✅ 落地 |
| **210** / 240 / 250 / 400 / 412 字 | ❌ 一条都没落地 |

而且 1 行、4 行、6 行、12 行**结果一样** → 限制是**字数**，与行数无关。
结论：**账号通道（Playwright 打字发送）单条上限 200 字，超了平台前端直接不收**
（Enter 无效、**不报错**）。官方 Bot API 那条路是 10000 字 ——
所以"长回复"在 Bot 通道正常、**在账号通道全灭**。

（这解释了为什么只有茶水间出问题：那里没绑 Bot；也解释了为什么短回顾能发、
400+ 字的富格式回顾全灭。）

## 3. 两个真 bug（都已修）

| # | 问题 | 修法 |
|---|---|---|
| 1 | 账号通道发长消息**静默失败** | 新增 `_split_for_account(text, ACCOUNT_MSG_MAX_CHARS=190)`：优先在**换行处**切、单行超长才硬切；`Sender._send_locked` 把长消息切成多条依次发，**每条都读回验证**；任一段没落地就判失败（账号失败不会被出站队列自动重发，所以不会产生重复） |
| 2 | **Socket.IO 兜底"假成功"** | `socketio.DZMMSocket._try_send` 只看 `status_code < 400` 就返回成功，`_fallback_send` 直接采信 → 出站队列记 `sent`、群里什么都没有。现在兜底也**读回验证**，读不到判未投递 |

## 4. 验收（自检群，真发真读回）

```
长消息字数 = 300  行数 = 12
切分预览 = [162, 137]
✂️ 长消息切成 2 条（每条 ≤190 字）
长消息 send -> True (16.3s)

最近 8 条里我们发的: 6
   len=162 首行='🤖 📮 你不在的时候（最近 3 小时 · 09-29 08:23 ~'
   len=137 首行='· 苏白和G_百戏聊彩票，G_百戏中奖转正了，苏白说正数就辞职、琰晏'
```

**两段都落地了** ✅（之前这条 100% 失败）。

测试：`tests/test_account_msg_limit.py`（10 条：切分规则、边界、真实回顾形状、接线、
兜底读回）；全量 **1246 收集 / 0 失败 / 4 跳过**。

## 5. 复盘

- **"没反应"要先分清"没生成"还是"没发出去"**：日志里 `📮 回顾:` 明明打了、
  `💬` 那行回复文本也打了，说明生成没问题 —— 问题在投递。**光看"任务跑了"会误判**。
- **"已发"是个需要证明的状态**：出站队列记 `sent`，但那次 `sent` 来自一条
  只看 HTTP 状态码的兜底路径。**凡是"我以为发出去了"，都得有一次读回**。
- **平台限制要靠夹逼，别猜**：官方文档写的是 10000 字（那是 Bot API 的），
  账号通道是 200 字 —— 两条通道的契约**不同**，而我们的代码把它们当成了同一个。
- **同一个 bug 会在别处长出来**：玫瑰房的星象卡（18~20 行）如果哪天回退到账号通道，
  会以完全相同的方式静默消失。`ACCOUNT_MSG_MAX_CHARS` 现在覆盖所有账号侧发送。
