# P12-AK：顶层茶水间的缺勤回顾（@她问"我不在的时候群里发生了什么"）

> 屋主 2026-09-29："我想让小小糯在**顶层茶水间**增加一个功能，就是 @ 她问『我不在的时候
> 群里发生了什么』这个功能。你先看一下可行性，给我一个方案。"
> 过程中改了三次口径，最终是：**只用小小糯～账号** / **忽略打卡、摸鱼躲藏、记忆考核内容**
> （不再要求"忽略别的 bot"）/ **窗口默认短一点** / **输入内容要丰富完整一些**。

---

## 1. 可行性结论：功能早就有，缺的是"把这个群接进来"

`runtime/recap.py` 的缺勤回顾（认证群一直在用）就是干这个的：@她 + 命中"我不在 / 错过 /
发生了什么 / 有啥事 / 有瓜吗 / 群里咋了" → `recap_absent()` → 固定三段
（💬 聊了什么 / 🎭 玩过什么 / 📌 等你回），其中「🔔 有人找你：XX 提到你 N 次」是
**代码算的**，不让模型编。

平台侧实测（`tools/probe_tea_room.py` / `probe_tea_room2.py`）：

| 项 | 结果 |
|---|---|
| 群 | `顶层茶水间--泛亚太色色摸鱼[G]公司` = `4fc4a2fd-465a-4436-9884-dbb5e60c6af2`，`group`，**779 人** |
| 侧车账号「小小糯～」 | **在群里**（`chat.listAll` 可见、`unreadMessages=94`、`getChatUser` 查得到、`isMuted=False`）→ 能读历史、能发 |
| 小小糯-bot | **不在群里** → 官方 Bot 发不了；屋主也定了"这个群只用账号"→ 走 Playwright（署名「小小糯～」，2-5 秒/条） |
| 成员表坑 | `chatroom.getMembers` 只返回 **101** 条（真实 779）→ 第一轮探针误判"不在群里"，用 `unreadMessages`/`getChatUser` 交叉证实了 |

## 2. 取证：噪音长什么样（这决定过滤怎么做）

`tools/probe_tea_noise.py` 取样 100 条，**41% 是噪音**：

| 噪音 | 谁发的 | 长什么样 |
|---|---|---|
| 摸鱼躲藏 | `总监事「bot」`(311a2438)，一人 38 条 | "XX，躲猫猫开始，开局不扣除…请选择一个地点：1（…）"、"【巡查】巡查 1（…）" |
| 记忆考核 | 同上 | "第 3 级通过。现在收手可获得 3 摸鱼币…"、"恭喜 晓 完成第 5 级记忆考核" |
| 打卡/彩票 | 同上 | "✅ 已购 5 注（10 摸鱼币）　🎲 机选号码" |
| **游戏指令** | 群友 | `/开始摸鱼躲藏`、`/躲 3`、`/记忆考核`、`/答案 D4BfI`、`/继续`、`/帮助` |

⚠️ 这里有个**必须一起解决的连带风险**：主循环把 `/xxx` 一律当"给我的指令"，
一接进这个群，779 人的群友每条游戏指令都会换回一句"这个我不会" = 刷屏。

## 3. 改了什么（代码 5 处）

| 位置 | 改动 |
|---|---|
| `runtime/features.py` | 新功能 `slash_cmds`（"接群内斜杠指令"，**默认开＝今天的行为**）：关掉＝这个群不接 `/` 指令 |
| `bot.py` 扫描循环 | `t.startswith("/")` 时先看闸门，关掉直接 `continue`（那些 `/xxx` 让给别家 bot） |
| `runtime/features.py` | `recap` 新增两个**按群**参数：`recap.default_hours`（默认 6，原来写死）与 `recap.ignore_kw`（忽略关键词，空＝不过滤，**所以别的群一个字不变**） |
| `runtime/recap.py` | ① 默认窗口改用 `recap.default_hours`；② 噪音过滤：命中 `ignore_kw`、**或**本群不接斜杠时的 `/xxx`，都不进转录、也不算"有人找你"；③ **转录更完整**：不再砍到 80/100 字（单条封顶 300）、非文字补 `[图片]/[语音]/[表情]/[撤回]`、每条前带 `HH:MM`、跨天插 `— 09-29 —` |
| `brains.py` | `generate_recap` 输出预算 400 → **800 token**（输入变全了，输出也该有地方写） |

## 4. 配置怎么接的（`tools/add_tea_room.py`，走 `config_store.save` 校验+备份+原子写）

- group 条目：`alias=顶层茶水间`、`enabled`、`persona=nuo`、`screen=false`、`push=false`、
  **不绑 Bot**（走账号）；
- **功能白名单**：只开 `chat` / `recap` / `memory_remember` / `memory_recall`，
  其余 **63 项显式关掉** —— 因为 `_feat_on` 默认全开，不管的话她会在 779 人群里
  主动发早安/午间记忆汇报/排行推送/入群欢迎；
- `scopes.recap = [认证群, 顶层茶水间]`（**覆盖语义**，必须两项都写，别把认证群弄丢）；
- 本群 tuning：`recap.default_hours=3`、`recap.ignore_kw=打卡,摸鱼,躲藏,躲猫猫,巡查,记忆考核,摸鱼币,机选号码`；
- ⚠️ **groups 不热加载 → 重启容器**（scopes/tuning 本来就热加载）。

## 6. 还没验的一环

**真实发送路径**没验：这个群没有 Bot，发送走账号（Playwright 打字），
而群里 779 人 —— 我不会未经允许往里发东西。**请你在群里 @ 她问一次**，
确认：① 有回复；② 耗时几秒；③ 署名是「小小糯～」。
如果发送失败（`Sender` 在该群可能有未知障碍），我再去查。

## 7. 复盘

- **"加个功能"往往不是加功能**：recap 早就有，真正的工作量在"接群 + 只开这一个 +
  把那个群的噪音规矩写进配置"。
- **接一个新群 = 打开 67 个开关的默认值**：`_feat_on` 默认全开，所以 `add_tea_room.py`
  里那份"显式关 63 项"的白名单不是洁癖，是防止她在 779 人群里自动播报。
- **过滤要先取证**：一开始我准备按"忽略别的 bot"做（屋主后来改口），取证后发现
  噪音里既有 bot 的播报、也有**群友发的游戏指令** —— 只看发送者会漏掉一半，
  所以最后是"关键词 + 本群不接斜杠时的 `/xxx`"两条规则。
- **探针自己也会说谎**：`F.on()` 不加载覆盖就按代码默认值答，差点让我以为配置没生效。
  现在验证脚本里显式 `set_overrides`，并在注释里写明。
