# P12-AC：`@` 问答 —— 带上下文、能多写、用自己的知识答（2026-09-27 夜）

> 屋主的原话：「在 @bot 对话的时候，能不能带上下文并且多输出一些，另外根据 bot
> 自己的知识回答？」—— 三件都是真的缺，逐条改完，附线上实测。

---

## 一、改前是什么样（逐条对照）

| 项 | 改前 | 改后 |
| --- | --- | --- |
| **上下文** | 只喂**末尾 4 条**，而且 `is_self` 直接 `continue` ⇒ **机器人自己说过的话全被丢掉**（每句都像从零开始回答） | 按群参数 `reply.context_msgs`（默认 **20**）取最近 N 条，**含自己说过的话**（标成「我」）；`generate_reply` 内部写死的 `[-10:]` 也改成参数 |
| **长度** | `generate_reply` 默认 **400 token** + 提示词写「简洁，一般 1-3 句话（群聊里不要写小作文）」 | 按群参数 `reply.max_tokens`（默认 **800**，可 100-3000）+ 提示词改成「日常 2-6 句、约 100-300 字；值得展开的事就展开写清楚」，「不要分段落」放宽到「最多 2-3 段」 |
| **知识** | 提示词要求「不知道就说不知道」「天气/新闻/股价…不要编造」 ⇒ 爱答"这个我不太清楚，建议看看天气预报" | 明确的**知识口径**：用你自己的知识、经验与判断回答（常识/观点/典故/你的口味与立场都能直说，别人问你怎么看就直说）；不确定就说不确定但**别动不动拒答、别打太极**；只有实时/精确数据（天气、股价、比分、新闻、隐私）不许编 |
| 开关 | 「@ 回答」是一条**没有开关的隐式行为** | 新增功能 **`chat`**（问答回复，默认开）——可按群关掉；注册表 64 → 65 项 |

三份口径都改了：`prompts/CMD_PROMPT.md` + `brains.py` 的代码默认值（两者必须逐字一致，有测试钉住）、以及若瑾的人设正文（她原来写死「一到三句」「不知道就说不知道」）。

## 二、线上实测（真调模型，容器内）

**① 上下文 + 人设**：喂进一段多轮对话（其中两条是"我"自己说过的话），
结果是**接着自己的上一轮说**的：

```
[工作群/若瑾] 88 字
临屿，你这句问得倒是聪明，知道先探我的气口。

气还没消。不过跟你没关系，你好好站着，别学那些提需求的往枪口上撞。
倒是你，刚才那句"好好说话"是想劝我，还是想管我？想清楚再答。
```
（"提需求""好好说话"都是上文里的原话；改前这两句会被丢掉，她不可能知道。）

**② 长度**：寒暄 88 字；观点题 **295 字**（改前上限 400 token + "只写 1-3 句"）。

**③ 自己的知识**（问「你怎么看加班」）：

```
[工作群/若瑾] 295 字
加班这件事，我的看法很简单：它是工具，不是美德。
一个团队需要加班，通常说明两件事之一——要么活确实压到了某个节点，短期冲一下，
那就冲，认了，事后补回来；要么是排期、人手、流程本身有问题，那就别拿加班去填
那个坑，填不满的，只会把人的精力一点点磨干。把加班当文化挂在墙上夸的，多半是
在用员工的时间掩盖管理的懒。
……我的态度：该拼的时候我不含糊，但不接受无意义的耗。
你要问的是你自己该不该加，还是想问怎么跟上面开口不加——这两个我给的建议不一样。
```
认证群的**小小糯**同样给的是自己的看法（298 字，软糯口吻），没有打太极。

## 五、已知边界 / 没动的

- **房间（玫瑰房）那条路没动**：它有自己的上下文与人设口径，长度走 `room.reply_max_tokens`。
- 提示词里的"实时数据不许编"是**刻意保留**的：放开的是"用自己的判断答"，
  不是"允许编造今天的天气/股价"。
- 若瑾在**羞辱/发骚/调教**那几条专用提示词下的口吻不在本次范围（那几条有自己的口径）。
