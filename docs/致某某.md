# 致某某（一封信）

仅认证妹子群、有效人设为小小糯（nuo）。**代发起者**写给群里某一位的一封信，发在群里。

屋主 2026-10-07 口径：① 代发起者写；② 谁能被写不限；③ 不设冷却；④ 长度和「我的故事」一样、
不分章节、按信的格式；⑤ 不加互动引导；⑥ 允许「谁不想被写」的名单。

## 使用方式

本功能默认关闭。准备上线时，在认证群的配置中设置 `features.personal_letter=true`。

- `/致 某某`、`/致某某`：给这个人写一封信。
- `/致 某某 2026-08-01~2026-09-30`：可选，指定北京时间起止日期（含结束日）。
- `@小小糯 给某某写封信`、`@小小糯 致某某`、`@小小糯 写给某某的信`：同一入口，也可带日期范围。

不能指定群外的人，不能在茶水间或其他群调用，其他人设不响应。关闭功能或不在作用域内时，**不转交普通聊天模型**编一封信。

## 成品要求

**信的格式**，不分章节：

```
某某姐姐：

（正文第一段，穿插收信人的原话）
（正文第二段）
（正文第三段）

（寄语，25～50 字）

—— 代笔：小小糯 · 受「发起人昵称」所托
```

- **称呼由程序生成**，按群里现有口径：女生→「X姐姐」、男生→「X哥」、未知→只叫名字。
- **落款由程序生成**：写清是代谁的笔。因为信是**发起人的口吻**，不写这行就看不出是谁发的。
- 正文 3 段、每段 120～170 字，成品 **450～600 字**（提示词写「约 500，超 650 整篇作废」；程序接收 300～700 字）；寄语 25～45 字。实测 **518～641 字**。
- 三段对应三件事：**熟悉**（我怎么注意到你）→**欣赏**（你身上具体的、有依据的好）→**关心**（惦记 + 祝愿）。
- **时间点少量**：全信 2～4 处就够（照 `messages` 的 `day` 写），不要每句都带日期、不要写成时间线。

**开场每次都不一样**（2026-10-07 屋主：「为什么所有的开头都一样啊，都是我其实很早就注意到你了」）。
根因是**示例泄漏** —— 提示词里的示例形状第一句就是那句话，模型照抄。两头一起治：

1. 示例改成**只示范 JSON 结构与字段名**，并写明"里面的句子一个字都不许照抄"；
2. `_generate` 每次从 `personal_letter.ANGLES` 里 **随机取一个切入角度**塞进 payload（`angle` 字段）——
   从 TA 常在什么时间出现说起 / 从 TA 说过的一句让你记住的话说起 / 从 TA 做过的一件具体的事说起 …… 8 种。
   提示词要求第一段就按 angle 切进去，并**点名禁止**"我其实很早就注意到你了"这类万能句。

实测 8 封信：**开头 8/8 全不重复**，固定句式出现 **0** 次。

**引用**：整封信**至少要有一条 `[[message_id]]`**（一条都不引会被判无效），最好每段挂一条；
也不要自己先把原话抄一遍再补占位符（会变成同一句出现两遍）。

**口吻是本功能最容易串的地方**：「我」= 发起人，「你」= 收信人。提示词里写死了这一条 ——
否则模型会照着「我的故事」的习惯把收信人的经历写成"我自己"的。

## 取证：读的是**收信人**的归档

与「我的故事」最大的区别。查询同时限定认证群 ID 和**收信人 UID**，
所以引用的每一句都是收信人自己说过的话；**发起者本人的发言一个字都不进模型**。

- 过滤与分层取样完全复用「我的故事」（12 桶 × 每桶 12 条、每条最多 160 字、总正文 ≤24,000 字），
  关键词表同样含 `_ADULT_KEYWORDS`。
- 引用只能走 `[[message_id]]`，ID 必须真实存在于证据里；查不到 → 拒绝整封。
- 整封信**至少要挂一条真实原话**，一封完全不引用的信没有依据可查，直接判无效。
- 归档里收信人的发言少于 3 条（或总正文不足 40 字）→ 直接回「还不太了解 TA」，不调模型。

## 目标解析：**不猜**

`runtime/chat_archive_query.find_senders()` —— 只读归档、零 API、**返回所有候选**：

| 情况 | 行为 |
|---|---|
| 唯一命中 | 直接写 |
| 两个以上命中 | 回一句「对得上好几个人：A、B、C。写全一点再试一次？」**绝不取第一个** |
| 一个都没有 | 回「没在认证群里找到这个人」 |

匹配优先级对齐 `runtime/members._find_uid_by_name`：精确（归一化后）→ 前缀 → 子串
（**单字不参与子串匹配**，「裳」不许命中「裳姐姐」）；档案里的当前昵称也算数，改过名也找得到。

> ⚠️ 这不是过度设计：**真库上就存在重名** —— 光「过期少女」这个名字就有两个 uid
> （一个 2,723 条发言，一个 1 条）。猜错就是把 A 的信写给 B。

## 保护措施

| 措施 | 说明 |
|---|---|
| 不想被写 | 环境变量 `DZMM_LETTER_OPTOUT=uid1,uid2`（逗号分隔，中文逗号也行）。名单里的人被 `/致` 时回「说过不想被写」 |
| 每人冷却 | `personal_letter.cooldown` 默认 300 秒 —— 同一个人不能连点 |
| 全群单在途 | 同一时刻只有一封信在生成（一封 10～20 秒），天然把"刷屏"串行化 |
| 目标级冷却 | `personal_letter.target_cooldown` **默认 0 = 关**（屋主口径「不设冷却」）。真正兜底的是"全群单在途"；这个参数只留着 —— 万一有人反复给同一个人写，后台改个数字就能开，不用重新部署 |
| 失败不吃冷却 | 生成失败会退回冷却，用户可以直接再发一次 |
| 不编共同经历 | 提示词禁止"那天我们一起……"这类没有证据的具体情节 —— 代笔不能把发起人没做过的事写成事实 |

## 与「我的故事」「我的画像」的关系

| | 我的故事 | 我的画像 | 致某某 |
|---|---|---|---|
| 读谁的归档 | 发起者本人 | 发起者本人 | **收信人** |
| 口吻 | 对发起者说"你" | 对发起者说"你" | **"我"=发起者，"你"=收信人** |
| 形状 | `一、XXX` 分段 | 3～4 个维度 | **信件：称呼 + 3 段 + 寄语 + 落款** |
| 长度 | 500（450～600） | 450～600 | 500（450～600） |

三者共用 `ask_and_render()`（失败带原因重试）、`insert_quotes()`（引文核验 + 自动补引号）
和同一组字数上下限，所以改动一处三家一起受益。
