# 妹子认证群 /生图

## 用法

- `/生图 提示词`：生成一张图片。
- 回复本群一张图片，发送 `/生图 修改要求`：以原图进行编辑。
- 可继续引用机器人生成的图片修改；可用既有 `/保存` 收进图集。
- `/生图` 显示用法。提示词最多 2000 字；引用文字、视频、损坏图片或无法核验的原消息时拒绝，不悄悄转成文生图。
- 收到任务时提示“前面还有 N 张图排队，另有 M 张图正在处理”；两类分别统计，取消/失败完成的任务不占排队数。
- 生成图片原生引用本次最初的 `/生图` 指令。图生图结果引用修改指令，而不是被修改的源图；恢复发送仍引用同一原指令。

## 实现与配置

`runtime/imagegen.py` 负责明确指令、原消息核验、xAI 调用和后台任务。文生图使用 `POST https://api.x.ai/v1/images/generations`；编辑使用 `/edits`，以 `image.type=image_url` 和 Base64 data URL 传入原图。模型为 `grok-imagine-image-2.0`。客户端遵循进程现有代理环境，使用 TLS 验证、禁止 API 重定向、不自动重试生成请求。

功能注册为 `imagegen`，默认关闭；硬范围仅 `PRIMARY_CID` 妹子认证群，另受 `slash_cmds` 总开关约束。`config.example.json` 示范仅在该群的 `features` 下设置 `imagegen: true`。仅修改模板不改变运行配置。指令无需 @，不受群内其他玩法的命令兜底影响；其他群不会生成或走闲聊兜底。

环境变量：

| 变量 | 用途 |
|---|---|
| `XAI_API_KEY` | 仅机器人实例 A 使用，从运行环境注入，代码不包含 key |
| `DZMM_IMAGEGEN_DB` | 默认 `data/imagegen.db`，机器人和图集 API 必须共享同一持久文件 |
| `DZMM_IMAGEGEN_PUBLIC_BASE` | 默认 `https://www.nuonuo.pw/api/gallery/generated`，机器人、图集服务使用同一值 |

按群参数：`imagegen.cooldown=60` 秒、`imagegen.input_limit=2000` 字、`imagegen.timeout=150` 秒。最多 2 个生成/发送任务同时工作，另可等待 5 个；每人仅一个在途任务。下载原图、模型请求与消息发送在后台进行，不占住群的命令处理循环。

## 图片保存与发送

`runtime/imagegen_store.py` 单独存储任务、原指令引用快照（含该条指令正文）与图片原始字节，不加入公开图集，不存储源图或 xAI key。生成结果使用 256 位随机 token 地址 `/api/gallery/generated/{token}`，不提供枚举/列表接口，不依赖 xAI 临时 URL；地址持有者可以读取该张图片。接口不需要 Gamefy 登录，便于平台拉图，但不会开放现有私密相册。

为支持图片原生引用，生成结果首先使用 `OutboxSender → RoutingSender → Sender.send_photo_reply_with_id → SioSubscriber`，以“小小糯”账号身份发送一条 `image + reference` 消息。账号连接不可用或平台明确拒绝时，改走本群官方 Bot；两个通道都未就绪才在请求 xAI 前拒绝。排队提示仍走原文本发送通道，其他图片功能保持现有路由。

出站类型仍为 `generated_image`，不进入普通文本自动重试器。账号 ACK 后再按消息编号回读，必须同时核对发图账号、`content.type=image`、引用指令编号、作者和正文。账号发送不明确时不切换通道；官方 Bot 发送不明确时也保留 `delivery_unknown`，避免重复发送。

2026-11-02 核对平台公开 Bot 文档及网页上传代码：`sendPhoto` 仅接受平台自有存储 URL，不能直接传我们的生成图地址。`runtime/generated_media.py` 在兜底发送前用账号 HTTP 会话调用 `chatroom.uploadImage`（multipart `file` + `chatroomId`），把已保存原图上传至平台并缓存返回地址，再调用官方 Bot。上传未成功时保留原图；不把图片 URL 当文字发群。此上传步骤仍需要有效账号 HTTP 会话，Socket.IO 断线不等于 HTTP 会话失效。

官方 Bot 接口没有已确认的原生引用参数，兜底图片不保证保留原生引用；普通账号通道继续严格核验原始指令引用。官方 Bot 的图片也回读确认类型才标记发送成功。图片结果不自动过期，以免历史群消息失效。

任务以 `(群编号, 指令消息编号)` 持久去重。进程重启后，排队/生成中的旧任务记为 interrupted，发送中的任务记为 delivery_unknown，均不自动重新生成。明确发送失败或仅已保存的 ready 任务，可由运维重放同一原指令恢复发送，复用原图、不再次调用 xAI；发送状态不明确时须先核对群历史。

旧 `imagegen.db` 自动增加可空的 `reference` 列，已有图像和任务状态不变。旧 ready 结果首次恢复发送时回查原指令、核验群和发起人并保存引用，不重新生成。

## 本地验证与启用边界

测试覆盖真命令分派、无 @ 入口、引用缺失回查、伪造引用地址不被采用、跨群与成员权限、队列/冷却、重复推送和重启去重、发送明确拒绝与不明确失败、原图持久读取、图集保存兼容及真实 HTTP 请求形态。

2026-11-02：使用实际 xAI key，通过本次新增 `XaiClient` 完成橘猫照片到水彩画的图生图测试，1024×1024，13.7 秒。首次连接失败经无计费的 `/v1/models` 探测确认是本机直连超时，遵循现有代理环境后成功。key 通过隐藏输入只进入测试进程内存。

同一客户端文生图也成功，1024×1024，16.9 秒。相关回归共 526 项通过，覆盖生图、命令、图集/私密图集/视频、配置、发送路由、出站队列、按群并行与功能管理页面。旧配置子进程测试需设置 `PYTHONUTF8=1`，否则 Windows 父进程按本地代码页解码 UTF-8 子进程输出会失败；补齐运行环境后通过，未修改该旧测试。

独立测试入口：`python tools/probes/probe_imagegen.py --prompt "修改要求" --image "原图路径" --out "新输出路径.jpg"`；不传 `--image` 即文生图。没有进程环境 key 时使用隐藏输入，不访问 DZMM 群聊。

本次为本地实现，未提交、推送或部署，未向真实群发送测试消息。生产启用时需同时更新机器人 A 与图集 API 的代码/镜像、注入 key、共享 `imagegen.db`，并仅在妹子认证群打开 `imagegen`。图集服务目前固定旧镜像标签，仅重启旧容器不会获得新图片路由；应部署包含新路由的镜像。现有 Caddy `/api/gallery/*` 转发可直接复用。
