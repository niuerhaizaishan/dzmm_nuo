# P12-R：房间触发口径收紧（为了"别误触发"）

> 起因：糯糯 2026-09-27 在群里说"不然误触发率太高了"，屋主随后确认"全做"。
> 判断依据是**当天玫瑰房 20 条房间触发**的分类：带「薇丝」/@ 的 11 条全部是有意叫她的，
> 误触发**全部**来自纯关键词触发。

## 1. 实测的误触发（原文）

| 消息 | 命中的规则 | 问题 |
| --- | --- | --- |
| `@橘先生（贱畜桃灼的主人） 小橘！摘个花试试！` | 花名 + 摘取动词 | 在**议论**别人摘花，管家差点演女鬼剧本 |
| `速配星座：天蝎座` | 星座词 | 客人**复读我们卡片上的那一行**，管家又发一张卡 |
| `想喝…` 类点单动词 | 点单动词 + 菜单词 | 闲聊里随时出现 |

## 2. 新口径（A + B + C，全在 `runtime/sign.py::_is_room_trigger`）

| | 规则 | 说明 |
| --- | --- | --- |
| ① | **被点名**（@薇丝 / 说出"薇丝"）→ 一定接 | 唯一的对话入口 |
| ② | **主人的指令**（改布局 / 女鬼上场）→ 不要求名字 | 信号强；屋主 @ 别人时也算 |
| ③ | **@ 了别人**的消息 → 关键词规则一律不认 | `_at_others()`；覆盖摘花/星座/点单 |
| ④ | **星座运势**保留自动，但**卡片复读**不算 | `_CARD_ECHO_RE`：`速配星座：`/`幸运颜色：`/`今日星象 ·`… |
| ⑤ | **客人点单必须点名** | 原来"想喝一杯酒"就能触发，是误触发大户 |
| —— | 摘花 / 报生日 / 星座问答 照旧自动 | 房间的招牌服务与确定性玩法不受影响 |

## 3. 线上实测（13/13 与预期一致，用当天真实原文）

```
OK @橘先生（贱畜桃灼的主人） 小橘！摘个花试试！   触发=False  ← 误触发① 已修
OK 速配星座：天蝎座                        触发=False  ← 误触发② 已修
OK 想喝一杯酒                            触发=False  ← 未点名的点单不再触发
OK 薇丝，给我来杯龙舌兰                      触发=True   ← 点名照旧
OK 摩羯座 / 摘花 / 我是金牛座                 触发=True   ← 招牌服务保留
OK 改成泳池（屋主）                         触发=True   ← 屋主自然说法也认
OK 改成泳池（客人）                         触发=False  ← 客人不能换布局
OK 今天天气不错                            触发=False  ← 纯闲聊
```

顺带修的两处：

- 屋主**不带名字**的自然说法（"改成泳池"）原来进不了闸门 —— 现在走
  `room_layout.is_layout_cmd` 一起认，和 P12-N 的发图判定对齐（同一句话：能触发才可能发图）；
- 卡片复读的识别同时认 `：` 与 `·`（卡片标题是 `今日星象 · 金牛座`）。

## 4. 一个旧测试跟着改了口径

`tests/test_feature_registry.py::test_room_order_gate_decides_whether_butler_answers`
原来断言"未点名的 `想喝一杯酒` 也触发"——那正是被 A 干掉的旧行为。它守的是
"`room_order` 开关管用"，所以改成用**点名的点单**来验证同一个开关（关掉 → 连点名点单也不接）。
