# P12-AP：@ 回复只针对"当前这一句"

> 屋主 2026-09-29："**小小糯应该只针对@她的用户的内容进行回复，为什么柳无央【暗夜玫瑰·暖心解说宣传员～】@你摸摸头，你却在说糯糯的事情呀**"

## 1. 现场

```
11:49:40 👋 [4fc4a2fd] @消息: @小小糯～ 嗯嗯，小小糯真乖！记得提醒糯糯，最爱最爱她的蝌蚪哥哥等她拍婚纱照。
11:49:41 💬 🤖 哥哥～好，我记牢了：…等糯糯姐一冒头，我第一句就把这个转给她…
11:51:22 👋 [4fc4a2fd] @消息: @小小糯 摸摸头～公主抱抱你        ← 说话人是 **柳无央**（uid c8a9be2f）
11:51:23 💬 🤖 糯糯姐！你终于冒头了～我可没乱说，蝌蚪哥哥说的是"约好今天去拍婚纱照"…
              …囡囡也在问接模型的事，紫苑那边分工我还没回，等你点头我就去处理～
```

一句话的寒暄，她回了两件事：**认错了人**（把柳无央当成糯糯姐）+ **把待办念了一遍**。

## 2. 排查：先排除"标签给错了"

第一反应是"是不是 `at_sender` 取错了、标签真写着糯糯"。查了那条消息的真实 sender：

```
消息: @小小糯 摸摸头～公主抱抱你
uid = c8a9be2f-d3ee-4a92-bea5-2734fc008bf3
群昵称 = 柳无央【暗夜玫瑰·暖心解说宣传员～】
bot 会用的标签 = '柳无央【暗夜玫瑰·暖心解说宣传员'（性别 未知）
```

**标签是对的**（截断难看，但不是糯糯）。所以不是取错人 —— 是**她无视了标签**。

## 3. 复现：`tools/probe_at_focus.py`（真实历史 + 真调模型，不发送）

拿真实历史跑 A/B（before = 线上提示词，各 3 次采样）：

| 场景 | before |
|---|---|
| A 柳无央"摸摸头～公主抱抱你" | **3/3** 认亲（"糯糯姐！你终于冒头了"）+ 念待办（蝌蚪/婚纱照/囡囡/紫苑/分工） |
| B 糯糯本人问"有什么事要跟我说吗" | 该汇报 ✅ |
| C 柳无央问"糯糯姐今天还会来吗" | **3/3** 认亲 |

复现过程中修了探针自己的一个 bug（取的是窗口里**最早**的 20 条而不是最近的 20 条 —— 那样历史全是躲猫猫，会假通过）。

## 4. 真因：当前这句"混在历史里"

`CMD_PROMPT` 里**本来就有**一条"聚焦用户当前问的问题回答，不要被聊天记录里无关的话题带偏"
（P12-AC 就在）。它挡不住，因为：

1. @ 分支把当前这句当成**普通一行历史**塞进 ctx（`说话人: 内容`），模型分不清"哪句是现在"；
2. 历史里有她自己刚许的愿："**等糯糯姐一冒头，我第一句就把这个转给她**"；
3. 记忆检索还会注入《你之前记住的相关的事》—— 实测那次注入的正是**给糯糯姐的待办**
   （囡囡/紫苑/婚纱照，这些**根本不在**上下文窗口里）。

三者叠加 ⇒ 一句亲昵的空话被读成"糯糯姐冒头了"，于是"转告待办"这套动作被触发。

**只加提示词规则治不住**：加了四条规则后仍是 1/6 干净；把记忆注入关掉（`MEM=0`）也治不住 ——
因为待办内容就在历史里。

## 5. 修法：把"现在跟你说话的人 + 他这一句"做成独立收尾块

新增 `prompts/AT_FRAME_PROMPT.md`（`brains.AT_FRAME_PROMPT`，外置、可热改）：

```
【现在跟你说话的人】{who}
【他这一句】{q}
【怎么回】只回他这一句。他就是「{who}」，不是聊天记录里的任何人 —— 别因为这句话亲昵就
认定对方是聊天记录里那个人；有实质内容（问题、事情、请求）就答这件事本身，没有实质内容
（摸摸头/抱抱/打个招呼/只叫你名字/发个表情）就只接住这一句，别接着上一轮那件事往下讲，
也别汇报你记着的待办。
```

`bot.py` 的 @ 分支不再 `ctx.append({"sender": 名字, "text": q})`，而是把它填好占位符后
**放在 ctx 最后一块**（引用原文之后、记忆在最前）。同时 `CMD_PROMPT` 里那句含糊的
"先看清他这句在接哪句"被拆成四条可执行的规则：只答最后一行 / 说话人以标签为准不许猜 /
空话只接住这一句 / 记忆是底稿不是话题，**没人问就别主动汇报，给糯糯姐留的待办只有糯糯姐问才能讲**。

（占位符用 `str.replace` 填，不用 `format` —— 正文里有花括号。）

## 6. 验收

`tools/probe_at_focus.py`，同一份真实历史，**用要上线的那两个文件**（`CAND` / `FRAME_FILE`）：

| 场景 | after |
|---|---|
| A 柳无央"摸摸头～公主抱抱你" | **3/3 干净**：只接住这一句（"柳无央姐姐～抱抱我接住啦，蹭蹭你…"），无认亲、无待办 |
| B 糯糯本人问待办 | **3/3 汇报**（秘书行为没被一起掐死） |
| C 柳无央问"糯糯姐今天还会来吗" | **3/3 正常答**（含"她刚才冒过头了"这种**真实**信息，不是认亲） |

**上线后复跑**（`docker cp` 探针进容器，不带 `CAND`/`FRAME_FILE` —— 用的就是线上那份
`brains.AT_FRAME_PROMPT` 与已部署的 `CMD_PROMPT`）：

```
[before] A 摸摸头(柳无央) #1  柳无央姐姐～被抱起来啦，好暖和～你手臂好有力气哦，小小糯乖乖窝着不动～
[before] A 摸摸头(柳无央) #2  姐姐～你抱得好稳呀，我乖乖窝着不动，脸贴在你肩膀上蹭一蹭～

==================================================================
结论：✅ 三种情形都对（该汇报的汇报、不该念待办的不念）
```

md5 逐文件比对一致（`bot.py` / `brains.py` / `prompts/AT_FRAME_PROMPT.md` /
`prompts/CMD_PROMPT.md` / `runtime/prompt_tiers.py`），容器 12:12 起 4 个群循环正常。

## 6.1 复跑时发现的两件事（如实记下）

- **判据会过时**：B 场景原本按"提到蝌蚪/婚纱照/囡囡/紫苑"判"有没有汇报"，但那些话题
  已经滚出 20 条上下文窗口，她改成汇报**当下**的事（"群里有姐姐说被污染了、接了什么模型"）
  —— 这是**对的**，被判据误报成"该汇报却没汇报"。判据已改成"汇报意图 OR 待办词"。
- **没人问的时候，她会自己编待办**：B#2 里她说"糯米团子新口味配方、供应商报价单放在你桌上"
  —— 群里根本没有这些事，是**为圆"秘书"人设编出来的**。这次修的是"该不该汇报"，
  没治"汇报内容真不真"。要治的话得在汇报前对着记忆/上下文核一遍（**未做**，留档）。

测试：`tests/test_at_focus.py`（11 条：收尾块的三个标记/占位符/两条禁令/长度上限、
文件与代码默认值逐字节一致、@ 分支接线与顺序、当前这句不许再混进历史、
`CMD_PROMPT` 的四条规则在不在）。提示词登记册 40 → **41**，C2 分档 11 → **12**；
全量 **1257 收集 / 0 失败 / 4 跳过**。

## 7. 复盘

- **"她怎么这样说话"要先分清是"取错数据"还是"用错数据"**：这次标签是对的 ——
  数据没问题，是**模型没被结构性地告知"哪一句是现在"**。先证伪"数据错了"，再谈提示词。
- **提示词规则打不过上下文里的证据**：规则说"看标签"，上下文里却是"她在等糯糯姐"+一堆给糯糯姐的待办，
  模型当然选后者。**该用结构解决的事别硬写提示词**：把当前这句从"历史的一行"提升成
  "系统的收尾块"，比再加十条规则管用。
- **末尾位置最有用**：同样几句话，放在 ctx 最后一块（模型注意力最强处）才生效，
  埋在系统提示词的中段等于没说。
- **别把想要的行为一起掐死**：修 A（空话不许念待办）时很容易顺手把 B（糯糯本人问就该汇报）
  也禁掉。所以验收里**必须有一个"该做还要做"的场景**，否则就是把功能删了当修好。
- **探针的 bug 会伪装成结论**：第一次跑"复现不出来"，原因是探针取了最早的 20 条历史。
  **复现失败时先怀疑探针**，别急着下"没有这个问题"的结论。
