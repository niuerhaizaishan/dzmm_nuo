## 2. 两个硬约束（决定方案形态，都是实测/读码得来）

1. **`#运势` 只加进触发词是没用的**。茶水间 `at_only=true`，而那段闸门在**指令判定之前**执行：

   ```python
   # bot.py:3212
   if _feat_on(cid, "at_only"):
       _by_at = is_at_me(t, cid); _by_quote = ...
       if not (_by_at or _by_quote):
           continue          # ← 没 @ 的消息（含指令）在这里就被丢弃
   if t.startswith("/"):     # bot.py:3218
       if not _feat_on(cid, "slash_cmds"):
           continue          # ← 茶水间 slash_cmds=false，`/xxx` 全被忽略
   ```

   所以必须**在 `at_only` 闸门之上**新开一条 `#` 入口。
2. **茶水间没有 Bot**，只能走账号通道。~~271 字的卡会**自动切成 2 条**~~
   —— **2026-09-30 已改（P12-AZ）**：账号的 Socket.IO 那条路不受打字框 200 字限制，

## 4. 限频（屋主定：冷却内**原样重发整卡**）

新增按群参数 **`fortune.cooldown`**（秒；默认 `0` = 不限频；茶水间设 `3600`）：

| 情形 | 行为 | LLM 成本 |
|---|---|---|
| 当天**第一次**问 | 生成整卡，并把**卡文本按 `uid + 日期`** 存进本群 state | 1 次（只写最后那句点评） |
| 冷却**内**再问 | **把缓存那张卡逐字原样重发**（同分、同点评） | **0** |
| 冷却**外**再问 | 重新生成（分数不变，点评是新的）并刷新缓存 | 1 次 |

- 缓存只留**当天**（跨天自动失效）；上限 780 人 × ~271 字 ≈ 210KB，可忽略。
- **`cooldown = 0`（默认值，认证群就是 0）＝ 从不复用缓存**，行为与现在**完全一致**。
- 缓存按 `cid` 分组存（命理历史、`_record_fortune`、`_pme(cid)` 都是按群的）。

## 5. 两个必须处理的坑

1. **`_ensure_decor` 会改卡**：`bot.py:3737`（`@` 分支收尾）会对回复跑
   `_ensure_decor(reply, p("chat_decor", cid))`。茶水间 `chat_decor` 为空只管住 ❤️，
   但 **`bang` 参数默认 True**（`runtime/text.py:27`）—— 正文里没有"！"时会把
   **最后一个"。"换成"！！"**，运势卡的点评句会被改。
   → **A2 这条回复必须跳过该后处理**（A1 走指令分支，本来就不走，与认证群一致）。
2. **`#` 入口必须在 `at_only` 之上**，且**只放行运势族白名单**：其他 `#xxx`
   原样走原逻辑（不吞别家 bot 的 `#` 语法，也不回"这个我不会"刷屏）。
   现状：全套代码里 `#` 只被本地工具用于解析配置文件（`grep startswith("#")` 无 bot 运行期用途），**前缀是空的**。
