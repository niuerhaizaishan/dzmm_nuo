## 一、通道归属总览（为什么侧车不可能退休）

| 依赖的平台能力 | 谁能做 | 用到的功能 |
|---|---|---|
| 收群消息 | Socket | 全部交互 |
| 发群消息 | 账号 **或** Bot | 全部回复 |
| **发超长消息** | **仅 Bot** | 公演小说、发骚场景、算命长文（账号有 1000 字符/10 换行限制） |
| 读历史 | **仅侧车** | 上下文、公演时间线、recap、表现总结、随机吐槽取材 |
| 成员昵称 | **仅侧车** | @解析、排行、按名查人 |
| 成员资料（性别/简介/签名） | **仅侧车** | `/查`、`/注册`、XP、算命、**性别筛查** |
| 踢人 | **仅侧车** | 踢游客 / 踢男性 |
| 认证状态 | **仅侧车** | 未认证提醒 |
| 私聊 | **仅侧车** | 吹牛骰子发牌、`/看骰` |
| 撤回 | ⚠️ **小小糯当前无此功能** | 全代码检索**没有** `message:recall` 路径；`_rollback_last_id` 回退的是**入站游标** `last_id`，不是撤回消息。若将来做撤回，必须走侧车 |

> 结论：**侧车永久存在**。迁移只把"群文本收发"搬到 Bot，其余一律留在侧车。

## 三、命令分派顺序（**必须逐字保持**）

顺序即行为。以下为 `bot.py:4520–4760` 的实际顺序（实测得出）：

```
 1  骰子系（精确匹配）        /吹牛骰子 /加入 /牌局 /看骰 /开始 /下一轮 /继续 /开 /退出 /结束 /N
 2  is_perf_end_cmd        （且 perf_active）
 3  is_perf_start_cmd
 4  is_story_end_cmd       （且 story active）
 5  is_vote_end_cmd        （且 vote active）
 6  is_fasao_end_cmd       （且 fasao active）
 7  is_dj_end_cmd
 8  is_diaojiao_cmd
 9  is_continue_cmd
10  is_rewrite_cmd
11  is_story_start_cmd
12  is_vote_start_cmd
13  is_help_cmd / is_guide_cmd
14  is_recall_cmd
15  is_intro_cmd
16  is_sync_cmd
17  is_trend_board_cmd
18  is_rank_cmd
19  is_summary_cmd
20  is_fortune_cmd
21  is_scene_cmd
22  is_poem_cmd
```

另有两条**不在主分派里**的路径：

- `is_dj_command_cmd` 是**兜底捕获**，规则是「裸 `/xxx` **减去一张显式排除表**」：
  ```python
  # bot.py:3149-3162 —— 它逐个调用其它判定，任一命中就排除自己
  if (is_help_cmd(cmd) or is_intro_cmd(cmd) or ... or is_vote_start_cmd(cmd) or ...):
      return None
  return body            # 其余一律当成调教命令
  ```
  实测它会吞掉 `/诗 糯糯`、`/周运`、`/生日`、`/吹牛骰子`、`/开`、`/退出`、`/同意` 等。
  ⚠️ **它只应在调教进行中由 `_check_diaojiao()` 使用**，绝不能提到主分派前面，否则会吞掉所有命令。
  ⚠️ **它是全项目重构风险最高的一段**：它依赖**每一个**判定的返回约定
  （`is_register_cmd(cmd) is not None`、`is_profile_cmd(cmd) != ""` …），
  任何一个判定的哨兵约定被改动，兜底行为都会**静默改变**。
  它没有排除的判定：`_is_stop_word`、`is_vote_end_cmd`、`is_review_cmd`、
  `is_trend_cmd`、`is_recap_cmd`、`is_trend_board_cmd`（→ `/同意` 因此会命中兜底）。
- `is_insult_cmd` / `is_devil_cmd` / `is_profile_cmd` / `is_register_cmd` / `is_vote_choice_cmd` / `is_review_cmd` 走 walrus 赋值形式（`elif (x := is_xxx(cmd)) ...`），不在上面的 `if/elif is_...` 列举里。

## 四、实测出的重叠与陷阱（**重构高危项**）

`tools/cmd_matrix.py` 实测结果。**这些不是 bug 报告，是"现状行为"**——重构时若顺序变了，行为会静默改变。

| # | 命令 | 同时命中 | 危险 |
|---|---|---|---|
| 1 | `/投票结束` | `is_vote_start_cmd` **和** `is_vote_end_cmd` | 若**无进行中的投票**，结束判定被 `active` 挡掉 → 落到开始判定 → **开出一个标题为"结束"的投票** |
| 2 | `/发骚结束` | `is_fasao_cmd`、`is_scene_cmd`、`is_fasao_end_cmd` | 无进行中发骚时 → 落到 `is_scene_cmd` → **开一场目标为"结束"的场景** |
| 3 | `/调教结束` | `is_diaojiao_cmd`（返回 `'结束'`）、`is_dj_end_cmd` | 无进行中调教时 → **开一场目标为"结束"的调教** |
| 4 | `/吐槽开` `/吐槽关` | `is_devil_cmd`（返回 on/off）、`is_insult_cmd`（返回 `'开'`/`'关'`） | 顺序错则把 `开`/`关` **当成人名去羞辱** |
| 5 | `/发骚` | `is_fasao_cmd` **和** `is_scene_cmd` | 两个功能抢同一命令词，靠顺序区分 |
| 6 | `/结束` `/停止` | 5 个结束判定 + `_is_stop_word` | 多状态同时 active 时靠顺序决定先结束谁 |
| 7 | `/记忆` | `is_recall_cmd` **和** `is_remember_cmd`（返回 `'忆'`） | 载荷解析差异 |
| 8 | `/我不在的时候群里发生了什么` | `is_summary_cmd` **和** `is_recap_cmd`（返回 `'的时候群里发生了什么'`） | `is_recap_cmd` 的前缀剥离疑似少剥了"我不在"，载荷看起来不对 |

### 返回约定不统一（**类型化重构的最大陷阱**）

用"拿一句非命令（`随便聊聊`）探测每个判定的返回值"实测得出：

| 约定 | 判定 | 含义 |
|---|---|---|
| `False` | 多数布尔判定（`is_help_cmd`、`is_scene_cmd`…） | 不是命令 |
| `None` | `is_devil_cmd`、`is_register_cmd`、`is_insult_cmd`、`is_diaojiao_cmd`、`is_poem_cmd`、`is_review_cmd`、`is_trend_cmd`… | 不是命令 |
| **`""`** | **仅 `is_profile_cmd`** | **不是命令**（docstring 亦写"空串表示不是"） |
| `""` | `is_register_cmd` / `is_rewrite_cmd` / `is_diaojiao_cmd` | **是命令，但无载荷** |

⇒ **同一个空字符串，在 `is_profile_cmd` 里是"不是"，在 `is_register_cmd` 里是"是"。**
`runtime/contracts.py` 做类型化时**不能**把它们盲目统一成 `str | None`，
必须先逐判定确认语义，否则 `/查`、`/注册`、`/重写` 的判定会整体反转。

**其它实测细节**

- `_is_stop_word` 不是子串匹配：先 `strip().lstrip("/")`，再对
  `停止/停下/结束/终止` 做**相等或前缀**匹配。
  ⇒ `/结束` 命中；**`/投票结束`、`/调教结束`、`/发骚结束` 不命中**（这也是它们没被
  generic 停止词提前吃掉的原因）。
- 返回空载荷（"是命令但无载荷"）的实例如 `/注册`、`/重写`、`/写诗` ——
  下游需自行处理空串，旧版矩阵脚本曾把它误判成"未命中"。

**做 P4/P8 时的硬性要求**：主分派顺序不得调整；若要重排，必须先在本清单登记并补回归测试。
