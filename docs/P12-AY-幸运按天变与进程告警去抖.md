## 一、幸运（颜色·数字·方位）按天变

### 现象/根因

`runtime/fortune.py::_WX_LUCK` 每个五行只给**一个固定三元组**：

```python
_WX_LUCK = {"木": ("竹青", "3", "正东"), "火": ("绛红", "7", "正南"), ...}
```

按名格五行取 ⇒ 同一张卡上"分数天天变"了，但 `🍀 幸运` **永远一样**（P12-AX 的同款毛病）。

### 修法

每种五行给 **3 个候选**，用"**日序数 + 名字长度**"取模：

```python
luck = opts[(dt_now.toordinal() + len(name_ch or full)) % len(opts)]
```

日序数每天 +1 ⇒ **隔天必然换一个**（不会连着两天一样），同时保留一点"因人而异"。

### 验收（线上代码，离线生成、不发送）

```
2026-09-30  87 分  ('杏黄', '5', '正中')   阴阳 -3
2026-10-01  79 分  ('琥珀', '0', '西南')   阴阳 +3
2026-10-02  73 分  ('赭石', '5', '东北')   阴阳 -3
```

测试：`tests/test_fortune_luck_and_health_debounce.py`（隔天必换、仍落在本五行候选里、同日稳定）。

## 二、进程告警去抖（"双进程"误报）

### 现象

```
2026-09-30 09:19:59 告警已发: 双进程异常（2 个 bot.py 实例）
2026-09-30 09:25:00 告警已发:  | 恢复: 进程恢复正常（单实例）
```

中间**什么都没发生**：那是部署重建的一瞬间 —— 旧容器在退、新容器的 `entrypoint.sh`
还要先跑 `headless_relogin` 才启动 `bot.py`，所以进程数会短暂地数到 0 或 2。

（顺带一个同类教训：我当时的诊断命令 `ps -ef | grep -c "[b]ot.py"` 也算出过 2 ——
PowerShell 把引号吞了以后 shell 把 `[b]ot.py` 当 glob 展开成 `bot.py`，
于是 **grep 匹配到了自己的命令行**。**数进程要用 `pgrep -f`，别用带引号的 grep**。）

### 修法

抽出 `_process_count_debounced()`：数不到 1 时**隔 `PROCESS_RECHECK_SEC`(5s) 复核一次**，
只有复核仍然异常才告警；单实例时**一步都不多走**（巡检每 5 分钟一次，别自己拖节奏）。
与 CPU 那条"连续 N 次才告警"是同一个道理。

### 验收：拿下一次部署做了天然实验

| 部署 | 巡检结果 |
|---|---|
| 09:19:04 重建 | 09:19:59 **告警：双进程异常（2 个）** ← 修之前 |
| 09:31:30 重建 | 09:32:06 **巡检正常，无告警** ← 修之后（同款重建） |

同时确认：容器内 `ps` 只有 **1 个** `bot.py`（PID 27）、`restarts=0`、
SIO 已连接、近 4 分钟 0 条 ⚠️/❌。

测试：`tests/test_fortune_luck_and_health_debounce.py`（首次 2 个→复核 1 个不告警、
复核仍 2 个保持告警、单实例不走复核、复核等待 ≤15s）。

## 复盘

- **"修了一个字段没变"要顺手查同一张卡上别的字段**：P12-AX 修完分数，幸运还是死的 ——
  同一屏里的每个数字都值得问一句"它为什么天天一样"。
- **误报的代价是"狼来了"**：巡检每 5 分钟一条，部署又是天天在做，
  一次白喊就会让人开始忽略告警。**凡是有瞬时窗口的判据，都要有复核/去抖**。
- **诊断命令本身也会说谎**：`grep -c '[b]ot.py'` 那个"2"骗了我几分钟 ——
  数进程、数文件这类操作，**先确认工具自己的命令行会不会被算进去**。
