# P12-BN 方案：她还是会把男生叫"姐姐"（先不改，等拍板）

> 屋主 2026-09-30 17:3x："**而且她有时候还是叫男生姐姐，你看看什么问题先，给我方案**"

## 1. 现象（用真实数据量出来）

`tools/probe_wrong_sister.py`（茶水间最近 **1000 条**消息）：

```
她共 22 条回复；带性别称呼的 6 条 → 对 5 / 错 1（认错率 17%）
❌ 08:52:35 对 顾影（识别=男生）叫了 姐姐：
   '🤖 顾影姐姐～别打嘛，我这不是想攒点币嘛。糯糯姐都说了我也需要币的呀～…'
```

触发那条是 `@小小糯～ 怎么刷起来摸鱼币了，打屁股`，发问人 **顾影**：

| 性别两路 | 结果 |
|---|---|
| 本地档案 `_gender_label` | 未知 |
| 实时识别 `_gender_of`（查平台） | **男生** ✅ |
| 平台原始 `gender` 字段 | **male** ✅ |

⇒ **性别没认错**，错的是**称呼**。同一句里她还正确地叫了"糯糯姐"（女）—— 所以这不是
"性别识别失败"，而是"叫法没被管住"。

## 2. 根因（三条，按影响排序）

1. **每轮都出现的收尾块里没有任何称呼规则。**
   `prompts/AT_FRAME_PROMPT.md` 现在只有：【现在跟你说话的人】{who}（这里已经是
   "顾影（男生）"）、【他这一句】、【你手上真记着的事】、【怎么回】（只回这一句）、
   【写多长】（2~6 句 / 100~300 字）。
   —— 给了**性别标签**，却**没说要按它叫**。
2. **基础提示词里的规则离得远、示例偏。**
   P12-AL 已经在 `CMD_PROMPT` 里写过"先看性别再决定怎么叫 / 男生叫哥哥 / 未知别硬叫姐姐"，
   但：① 基础提示词很长，离当前这句最近的是上面那个收尾块；② **示例全是女生**（13 处"姐姐"）；
   ③ 收尾块又在讲"要写够 2~6 句"，注意力被更近、更具体的指令占走。
   P12-AL 当时就实测过"光写规则不管用，示例才管用"。
3. **群里的语气本身就是"见谁都叫姐姐"。** 茶水间里大家互称"姐姐""XX姐姐"（连男生也被
   这么开着玩笑叫），20 条上下文里全是这种语气，模型会**镜像**它。名字"顾影"本身也偏柔，
   进一步推高"姐姐"的概率。

⇒ 结论：**约 1/6 的带称呼回复会滑成"姐姐"**，属于"提示词压不住"的那一类问题 ——
和 P12-AL / P12-AH 遇到的是同一个性质（提示词能到 80%，剩下 20% 得靠代码兜）。

## 3. 方案

### A. 把称呼规则放进**每轮都出现的收尾块**（最有效、改动最小、热生效）

在 `AT_FRAME_PROMPT` 里【现在跟你说话的人】后面加一行，例如：

```
【怎么叫】只按上面括号里的性别叫：男生 → 名字或"哥"；女生 → 名字或"姐"；未知 → 只叫名字。
**绝不能叫男生"姐姐"**——群里别人拿性别开玩笑的称呼（把男生叫"姐姐"那种）你不要跟着学，
也不要把聊天记录里别人对他的叫法搬过来。
```

- **为什么放这里**：P12-AP/P12-AQ 的经验 —— **离当前这句话最近的那块最管用**；而且这个块
  每次都会带上 `{who}`（含性别标签），天然是"把标签变成动作"的地方。
- **代价**：改提示词（`prompts/AT_FRAME_PROMPT.md` + `brains.AT_FRAME_PROMPT` 逐字节一致），
  **热生效、不用部署**；要跑提示词契约测试 + 一次真生成 A/B。

### B. 确定性兜底（提示词管不住时用代码兜，和 P12-AL/AH 同一套路）

新增 `_gender_addr_guard(reply, addressee_name, glabel)`，**只纠正"指向收信人"的那个称呼**：

| 性别 | 处理 |
|---|---|
| 男生 | `顾影姐姐` / `顾影姐` → `顾影哥` |
| 未知 | `顾影姐姐` / `顾影姐` → `顾影`（去掉称呼） |
| 女生 | 不动（她现在对女生叫得对） |

**关键点：句中别人的称呼不动。** 真实的错句里同时有对有错 ——
`顾影姐姐～…糯糯姐都说了…` ⇒ 只把第一处改成"顾影哥"，"糯糯姐"保留 ✅
这就是它比"全局替换姐姐"强的地方。

- 位置：@ 闲聊路的后处理（紧挨 `_ensure_decor`），**只作用 @ 路**，玩法正文一个字不动；
- 命中时打一行日志：`⚧ 称呼纠正：顾影姐姐 → 顾影哥`（便于统计有没有好转）；
- 可选增强：命中就**重生成一次**（更自然，但多一次模型调用 +1~3 秒）。

### C. 数据层（这次不用）

性别两路都认对（`识别=男生`、`平台=male`），**不需要补数据**。
但要强调：**"未知"是最容易滑成"姐姐"的一类**（顾影的档案就是"未知"，只是平台查到了 male）
⇒ A 里"未知 → 只叫名字"这句要写死，B 里也要处理未知。

### D. 观测

把"称呼纠正次数"汇总进心跳/体检（或每周用 `probe_wrong_sister.py` 复扫一次），
目标是认错率 **17% → 0**。

## 4. 验收

1. **真实回归**：拿线上那条原句过一遍 B：
   `"顾影姐姐～别打嘛…糯糯姐都说了…"` → `"顾影哥～别打嘛…糯糯姐都说了…"`（只改第一处）；
2. **单测**（新文件）：男生被叫姐姐→改；女生被叫哥哥→改（对称保护）；未知→去掉称呼；
   句中**他人**称呼不动；女生被叫姐姐→不动；空回复/无称呼→原文返回；纠正要打日志；
3. **提示词**：`tests/test_prompts.py`（逐字节一致）；
4. **真生成 A/B**（`tools/probe_reply_length_ab.py` 的路子）：同一批输入各 10 条，
   数"男生被叫姐姐"的次数（改前 / 改后）；
5. **线上**：改完观察 3 天，用 `tools/probe_wrong_sister.py` 复扫。

## 6. 实施记录（2026-09-30 17:42 · 屋主选「先只做 A」）

### 6.1 做 A 的过程中**推翻了原来的根因判断**（重要）

按 A 写提示词之前先做了真生成 A/B，结果**带标签时 0/6 全对**（旧提示词本来就够）——
说明线上那次不是"提示词没管住"，而是**压根没拿到性别**。回头看那行代码：

```python
# bot.py:4013（@ 分支）
glabel = _gender_label(at_sender)     # ← 只看**本地档案**，不查平台
_who = get_name(at_sender) + ("（" + glabel + "）" if glabel != "未知" else "")
```

顾影的本地档案里性别是空的 ⇒ `_gender_label` 给"未知" ⇒ **标签被整个省掉**
⇒ 模型看到的只有"顾影"两个字，**零性别信息** ⇒ 按它惯常语气叫了"姐姐"。
（运势卡那条路 P12-BA 用的是 `_gender_label_of` → `_gender_of`（档案 + 平台实时查），
所以卡上叫对了 —— **两条路的性别来源不一致**，这才是真凶。）

**复现证据**（`tools/probe_sister_ab.py`，容器内真调模型，3 轮）：

| 用例 | 旧收尾块 | 新收尾块（A2） |
|---|---|---|
| 顾影（**带**"男生"标签） | 0/3 叫姐姐 ✅ | 0/3 ✅ |
| 苏白（带标签） | 0/3 ✅ | 0/3 ✅ |

### 6.2 A 做了什么

`prompts/AT_FRAME_PROMPT.md` + `brains.AT_FRAME_PROMPT`（逐字节一致）里加了一行，
紧跟在【现在跟你说话的人】后面：

```
【怎么叫】按上面的性别：男→"哥"，女→"姐"，未知→只叫名字。**不能叫男生"姐姐"**，群里这么开玩笑也别学。
```

- **长度**：436 → **453**（测试有 460 上限，为塞进这一行同时压掉了原文里的冗余措辞；
  锁死短语"不是聊天记录里/亲昵/别接着上一轮/只能讲上一行/真出现过/（空）/不许编/桌上/配方/
  100~300 字起步/今天怎么样/在干嘛/吃了没/摸摸头"等**一个没丢**，测试全过）；
- **上线方式**：`deploy.ps1 -Action upload`（只拷代码、**不重建不重启**）→
  `17:42:09 P12: 热加载 提示词 · AT_FRAME_PROMPT` / `热加载完成 来源=prompts prompts=1`；
- 容器内校验：`prompts/AT_FRAME_PROMPT.md` md5 `324b4c7f`（本地=容器）、

### 6.3 还留着一个根上的弱点（建议下一步做 A1）

现在她是**从上下文猜**顾影是男的（这次猜对了），而不是**被告知**。只要群里没人说过、
或者名字看不出来，还是可能滑。**真正的修法是让标签出现**：

```python
# A1（约 3 行）：@ 分支改用与运势卡同源的性别解析
glabel = await asyncio.to_thread(_gender_of, at_sender, cid)   # 档案优先，缺了实时查平台并写回档案
```

- 好处：标签从"常常缺"变成"基本都有"，P12-AL 的规则 + 这次的【怎么叫】才真正吃得满；
- 代价：**首次**遇到"档案没性别"的人会多一次平台查询（查完写回档案，之后不再查）；
  现在是同步函数，必须像其它平台调用那样套 `asyncio.to_thread`（@ 分支里已有同样写法）；
- 风险：多一次平台调用（有节流与失败兜底，失败就退化回"未知"，与今天行为一致）。
