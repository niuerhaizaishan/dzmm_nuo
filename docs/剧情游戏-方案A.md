## 一、定位

小小糯当 GM（主持人），开一段涩涩剧情。**群友不扮演角色，而是用投票共同决定剧情走向**，多轮推进到结局。

与现有功能的区别：

| 功能 | 群友角色 | 互动方式 |
|------|---------|---------|
| 公演 | 演员（S/M/围观） | 真人文字扮演 |
| 调教 | 发命令者 | 命令真人 |
| **剧情** | **集体导演** | **投票决策走向** |

## 二、核心流程

1. **发起**：`/剧情开始 [主角] [自定义剧情]`
2. **开局**：GM 生成场景（围绕主角）+ 3 个选项
3. **投票**：60 秒窗口，`/选 N` 或 `/N`
4. **推进**：最高票 → GM 生成下一段 + 3 个新选项
5. **循环**：默认 6 轮
6. **结局 + 结算**

## 三、主角设定

- **指定群友**：`/剧情开始 糯糯` → 糯糯当女主
- **指定 + 自定义**：`/剧情开始 糯糯 校园教室的深夜` → 糯糯当女主，剧情往"校园教室深夜"走
- **未指定主角**：从当前群发言成员里随机抽一个当女主
- **解析规则（最长前缀匹配，复用 `_parse_scene_target` 模式）**：
  - 开头第一个能匹配到群友昵称的 token = 主角
  - 剩余 token = 自定义剧情方向
  - 匹配不到群友 → 整段当自定义剧情，主角随机
- **随机主角的开局保护**：开局 @主角 一句"这局你是女主哦，不想当发 /剧情结束"给退出机会

## 四、剧情篇幅

- **篇幅充分、宁长勿缺**，不人为砍短
- 格式硬约束只有一条：**换行 ≤10 行**（DZMM 限制，超了整条发不出去）
- ⚠️ 技术边界：单条消息约 **333 中文字**（1000 字节）硬上限，生成端每段压在此范围

## 五、投票机制

| 项 | 设计 |
|----|------|
| 指令 | `/选 N` 和 `/N` 都认（N=1/2/3 或 A/B/C），降低操作成本 |
| 窗口 | 60 秒 |
| 提醒 | 剩余 30 秒、10 秒各发一次"还有 X 秒，快 /选 投票哦～" |
| 重复投 | 可重复投，以最后一次为准 |
| 无人投 | 超时无人投 → GM 兜底自选，提示"没人投，糯糯帮你选啦" |
| 平票 | GM 随机选 |

## 六、屏蔽（剧情进行中）

- **指令**：只放行 `/选 N`、`/N`、`/剧情结束`、停止词；其余（/发骚 /羞辱 /调教 /公演 /算命 /查询 等）全部屏蔽，提示"剧情进行中哦～先 /剧情结束"
- **自动触发**：屏蔽排行（12/18 点）、高潮事件、新成员欢迎、公演/调教互动等一切会"主动发消息"的触发，剧情期间群内只有剧情本身的声音

## 七、状态机（`state.json` 每群 `story` 字段）

```json
{
  "active": true,
  "phase": "等投票",
  "round": 2,
  "max_round": 6,
  "protagonist_uid": "a56cbd67-...",
  "protagonist": "糯糯",
  "custom": "校园教室的深夜",
  "votes": {"<uid>": 2},
  "vote_deadline": 1730000000,
  "remind_30": true,
  "remind_10": true,
  "history": ["第1轮剧情...", "第2轮剧情..."]
}
```

## 八、GM 生成（brains.py 三个 prompt）

- `STORY_START_PROMPT`：主角 + 自定义方向 → 开局场景 + 3 选项
- `STORY_STEP_PROMPT`：历史剧情 + 本轮被选选项 → 下一段 + 3 新选项
- `STORY_END_PROMPT`：完整历史 → 结局（意犹未尽、有余味）

文风沿用既定口味：色色、直白露骨、加羞辱、选项埋钩子。主角是真实群友，剧情围绕 TA 展开。

## 九、结局与结算

- 结局汇总 6 轮剧情收尾，留悬念
- 结算：投票者 `+8` 发情值，主角 `+15`

## 十、指令清单

| 指令 | 作用 |
|------|------|
| `/剧情开始 [主角] [自定义]` | 发起 |
| `/选 N` / `/N` | 投票 |
| `/剧情结束` | 提前结束 → 直接进结局 |
| `/停止 /停下 /结束` | 停止词（只认带斜杠） |

## 十一、技术边界与隐患

- 换行 ≤10 行、单条约 333 字（生成端控制）
- 剧情连贯性：`history` 每轮传入 prompt，GM 基于前文生成
- 和公演/调教互斥：剧情中发 `/公演开始` → 提示先 `/剧情结束`，反之亦然
- 提醒去重：`remind_30`/`remind_10` 标记，避免重复提醒
