> 但是人设以及其他不变。"

## 0. 先查证：临屿是谁、"差"到底在哪

`tools/probe_nuo_vs_ruojin.py` 查完发现**请求里能直接执行的部分早就一样了**：

| 项 | 认证群/小小糯 | 上班群/若瑾 |
|---|---|---|
| `reply.max_tokens` | 800 | 800 |
| `reply.context_msgs` | 20 | 20 |
| `chat`（@ 问答） | 开 | 开 |
| 群级 tuning 覆盖 | 无 | 无 |
| 滚动上下文（P12-AD） | 有 | 有 |
| **人设 extra 字数** | **0** | **1536** |
| 群里有没有叫「临屿」的 | **没有** | 有（uid `a4897fb3`，**是人不是 bot**） |

所以"临屿"指的是**屋主自己在上班群跟若瑾聊的那种体验**，不是某个可复制的配置。
而那份体验的四个组成里，**三个（上下文条数、回复长度上限、知识口径）本来
就是全局默认值**，P12-AC/P12-AD 改的正是它们 —— 认证群一直吃的是同一份。

## 1. 真调模型的 A/B（同一批问题，推提示词前后各一次）

`tools/verify_nuo_scope.py --tag before / after`：

| | 观点题（异地恋） | 知识题（失眠） |
|---|---|---|
| **before**（旧提示词） | 301 字 | **342 字** |
| **after**（本次） | 313 字 | 252 字 |

两轮都：不打太极 ✅、有她自己的观点 ✅、软糯人设没变 ✅。

也就是说 **before 就已经达标**了 —— 这也说明屋主在认证群看到的问题，
大概率是 **19:45 之前那次「没有上下文」的 bug**（它对每个群都生效，
认证群一样中招），而那个已经在 P12-AD 修掉并部署了。

## 2. 那这次到底改了什么

只剩一处结构性差距：**若瑾的 extra 里把那套口径又强调了一遍，而且落在 prompt
最末尾（recency 生效）；小小糯 extra 是 0 字**，且 `CMD_PROMPT` 里那 4 组
few-shot **全是 1-2 句的短回答** —— 模型照着示例学，比照着规则学长得多。
于是本次只动 `CMD_PROMPT.md`（小小糯那份主人格提示词）三处：

1. 长度口径点明"示例里的短句只是**寒暄**示范，不代表回答长度"，并**补上上限**
   （"别超过 300 字、别写成小作文刷屏"）—— 只往长里推会变成群里刷屏；
2. 【规则】加一条：**聊天记录里标着"我:"的是你自己刚说过的话**（承接 P12-AD
   的滚动记录：接着往下说、别重复问已经答过的、别把同一句再答一遍）；
3. 补一组**长回答示例**（约 200 字、有她自己的立场、仍是软糯"姐姐/～"口吻）。

**刻意不新增 persona extra**：`nuo` 的 extra 保持为空，"默认人设零开销原样返回"
这条既有不变量不动（`tests/test_persona_texts.py` / `test_persona_config.py` 钉着它），
也避免多出一份要同步维护的文本。

## 4. 复盘

- **"调成 X 那样"这类请求，先把 X 拆成可测量的项再动手。** 拆完发现 6 项里
  5 项已经相同，真正能改的只有 1 项 —— 如果不拆，很容易"改一堆没用的"，
  还顺手把已经对的东西弄坏。
- **人设与口径要分开管**：这次一个字都没碰外貌/性格/称呼/语气，
  只动了"怎么答"（长度上限、知识立场、连续性），并用测试钉住人设段还在
  （`test_the_persona_itself_is_untouched`）。
- **A/B 要有对照**：`--tag before` 这一跑证明了"本来就达标"，
  否则我会误以为自己的改动是"修复"，而实际上它只是**加固**。
- **加长要同时给上限**：只加"要答够"会把 342 字推到更长，群里就是刷屏；
  补上"别超过 300 字"之后知识题从 342 收到 252。

测试：`tests/test_nuo_scope.py`（11 条）；全量 1160 收集 / 0 失败 / 4 跳过。
